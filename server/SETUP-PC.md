# Задача для Claude Code на домашнем компе: каркас архива Правки

Ты работаешь на домашнем компе владельца (Саша). Это Windows, включён
всегда, у роутера постоянный внешний IP. Говори с владельцем по-русски, живо и
коротко, без канцелярита.

## Что строим и зачем

Правка — личное Android-приложение владельца: таймшит (Засечка), деньги, спорт,
еда, диктовка. Сейчас его данные живут на телефоне, и телефон их забывает:
тексты диктовок ротируются, еда хранится 420 дней, тренировки 120. Строим
**архив на этом компе**:

- PostgreSQL на диске D:, в нём журнал событий, который только дописывается;
- сервис на Python (код — в репозитории, папка `server/`, его пишет облачная
  сессия), а в нём три части:
  - приёмник событий с телефона: `POST /ingest` с токеном;
  - сборщик intervals.icu: забирает тренировки и wellness напрямую;
  - MCP-сервер для claude.ai: `/mcp`, вход по OAuth. Через него Claude отвечает
    на вопросы владельца о его жизни.

**Наружу.** До 01.10.2026 облако семьи публиковал прежний роутер Keenetic.
`rclone serve webdav` отдавал папку `D:\Oblako` на порту 8088 задачей
планировщика от SYSTEM, а роутер выводил его веб-приложением KeenDNS по HTTPS
на порт 8443 (443 Билайн резал до роутера, проверено 26.09). 01.10 владелец
поставил новый роутер, и эта публикация пропала.

Из-за этого облако семьи сейчас не работает:

- общие Деньги с Марианной не синхронизируются;
- ночные копии базы на этот комп не доезжают.

Данные не теряются: журналы и копии ждут на телефонах и уедут, когда сервер
снова будет доступен.

Поэтому публикацию строим так, чтобы она больше **не зависела от роутера**:
**одна входная дверь на самом компе** — Caddy с настоящим сертификатом.
Роутер только пробрасывает один порт. За этой дверью живут архив и, если
владелец его возвращает, WebDAV семьи. Подробно — шаг 7.

Эта задача делится на две части:

- **Часть А — подготовить машину и проверить сетевой путь.** Её делаешь сейчас.
- **Часть Б — развернуть сервис из репозитория.** Её делаешь, когда в ветке
  `pravka` появится `server/README.md` с разделом «Развёртывание».

## Чего нельзя

- **Не трогать файлы `D:\Oblako`.** Задачу rclone меняй только ради того,
  чтобы вернуть облако семьи за новую дверь (шаг 7), и только с согласия
  владельца.
- **Архив не класть внутрь `D:\Oblako`.** Эту папку видят по WebDAV все
  устройства семьи, а в архиве личные диктовки и деньги.
- **Postgres слушает только `127.0.0.1`.** Базу в сеть не выставлять никогда.
- **Секреты** (пароли, токены, ключ intervals):
  - живут только в `D:\PravkaArchive\secrets\`;
  - в репозиторий не попадают;
  - в чат целиком не выводятся: показывай первые 4 знака.
- **Перед необратимым — спросить владельца.** Это удаление, форматирование,
  перезапись чужих файлов, смена настроек роутера.
- **Роутер ты не настраиваешь.** Это делает владелец руками в его
  веб-интерфейсе, ты ведёшь по шагам и проверяешь результат.

## Часть А

### 1. Осмотреться и доложить

Прежде чем ставить что-либо, собери и покажи владельцу:

- версию Windows и наличие `winget`;
- физические диски (`Get-PhysicalDisk`, `Get-Partition`, `Get-Volume`):
  - лежат ли C: и D: на **разных физических дисках**;
  - сколько свободно на каждом.

  От этого зависит, защищает ли ночная копия от смерти диска.
- что уже стоит: Git, Python, PostgreSQL (версии);
- адрес компа в локальной сети и адрес роутера (шлюз);
- **новый роутер:** модель (спроси владельца или посмотри по веб-интерфейсу
  шлюза). Умеет ли он сам публиковать по HTTPS со своим доменом, как KeenDNS
  у Keenetic?
- **внешний адрес:**
  - сравни `Invoke-RestMethod https://api.ipify.org` с внешним (WAN) адресом,
    который показывает роутер;
  - совпадают — адрес публичный;
  - не совпадают — мы за NAT провайдера, и входящие соединения невозможны без
    туннеля: сразу доложи владельцу;
- **провайдер.** Если это всё ещё Билайн, помни: 443 он резал;
- задачу планировщика rclone: есть ли она, работает ли, на каком порту. С неё
  берём образец, как запускать службы;
- занят ли порт **8090** (`Get-NetTCPConnection -LocalPort 8090`). Если занят,
  возьми свободный рядом и дальше используй его вместо 8090.

### 2. Папки

### 3. Поставить

- **Python 3.12 или новее** (`winget`) — для всех пользователей, с `py`-лаунчером.
- **PostgreSQL 16 или новее** (`winget` или установщик EDB):

  - служба с автозапуском;
  - `listen_addresses = '127.0.0.1'`;

### 4. База и роли

От суперпользователя:

```sql
CREATE ROLE pravka LOGIN PASSWORD '<сгенерировать>';
CREATE DATABASE pravka OWNER pravka ENCODING 'UTF8' TEMPLATE template0;
CREATE ROLE pravka_reader LOGIN PASSWORD '<сгенерировать>';
ALTER ROLE pravka_reader SET default_transaction_read_only = on;
ALTER ROLE pravka_reader SET statement_timeout = '15s';
GRANT CONNECT ON DATABASE pravka TO pravka_reader;
```

Таблицы, виды и права на чтение создаёт сам сервис командой `migrate` в
части Б. Сейчас их не заводи.

Проверь, что входишь обеими ролями через `psql -h 127.0.0.1`.

### 5. Файл секретов

`D:\PravkaArchive\secrets\server.env` — строки `ИМЯ=значение`, без кавычек:

```
PRAVKA_DB_URL=postgresql://pravka:<пароль>@127.0.0.1:5432/pravka
PRAVKA_DB_READER_URL=postgresql://pravka_reader:<пароль>@127.0.0.1:5432/pravka
PRAVKA_LISTEN=127.0.0.1:8090
PRAVKA_PUBLIC_URL=
PRAVKA_INGEST_TOKEN=<64 случайных hex-знака>
PRAVKA_OWNER_PASSWORD=<см. ниже>
PRAVKA_BLOBS=D:\PravkaArchive\blobs
PRAVKA_LOGS=D:\PravkaArchive\logs
ICU_ATHLETE_ID=
ICU_API_KEY=
```

- **`PRAVKA_INGEST_TOKEN`** — по нему телефон доказывает, что он телефон.
  Сгенерируй криптостойко: `RandomNumberGenerator`, не `Get-Random`.
- **`PRAVKA_OWNER_PASSWORD`** — пароль, который владелец один раз введёт на
  странице входа, когда подключит архив в claude.ai.
  - Спроси, хочет ли он свой. Если нет — сгенерируй пять случайных русских
    слов через дефис: такое легко набрать на телефоне.
  - Покажи пароль владельцу один раз и попроси сохранить.
- **`PRAVKA_LISTEN`:**
  - `127.0.0.1:8090` — сервис за Caddy на этом же компе (основной путь, шаг 7);
  - `0.0.0.0:8090` — только если наружу публикует сам роутер.
- **`PRAVKA_PUBLIC_URL`** заполнишь в шаге 7.
- **`ICU_ATHLETE_ID` и `ICU_API_KEY`** вставляет владелец. В intervals.icu это
  Settings, раздел Developer Settings: там API key и Athlete ID вида `i12345`.
  Подскажи, где это. Если ключа пока нет, оставь пустым: сборщик intervals
  просто не запустится.

### 6. Брандмауэр

Зависит от пути из шага 7:

- **Caddy на компе (основной путь).**
  - Входящее правило TCP на публичный порт Caddy (например 8443), откуда
    угодно: это и есть дверь. Проброс порта сохраняет настоящий адрес
    клиента, поэтому «только от роутера» здесь не работает.
  - Сервис слушает `127.0.0.1:8090`, rclone — `127.0.0.1:8088`. Правил для
    них не нужно: снаружи их не видно.
- **Публикует роутер.** Входящее правило на TCP 8090, удалённый адрес —
  только роутер (шлюз из шага 1), профиль «Частная».

### 7. Публикация наружу — решаешь с владельцем

**7.1. Разведка.** Узнай, какие внешние порты доходят до компа:

1. Попроси владельца пробросить на роутере проверяемый порт на комп.
2. Запусти на этом порту на время простой ответчик
   (`python -m http.server <порт>`).
3. Попроси владельца открыть `http://<внешний IP>:<порт>` с телефона **по
   мобильной сети**, не по домашнему Wi-Fi.

Проверь 443, 8443 и 80. Запиши, какие прошли, и закрой лишние пробросы.

**7.2. Основной путь — Caddy на компе.**

- **Имя.** Если у владельца есть свой домен — поддомен, A-запись на
  постоянный IP. Если нет — бесплатное имя DuckDNS (`<имя>.duckdns.org`,
  A-запись на IP). Токен DuckDNS храни в `secrets\`.
- **Сертификат** — Let's Encrypt через DNS-проверку (DNS-01). Для неё не
  нужны открытые 80 и 443. Caddy для Windows бери сборкой со встроенным
  модулем своего DNS: на caddyserver.com/download, модуль `dns.providers.duckdns`
  или `dns.providers.cloudflare`.
- **Caddy — служба:** задача планировщика от SYSTEM при старте системы, с
  перезапуском, по образцу rclone. Caddyfile примерно такой:

  ```
  {
      auto_https disable_redirects
  }
  <домен>:8443 {
      tls {
          dns duckdns {env.DUCKDNS_TOKEN}
      }
      handle /dav/* {
          reverse_proxy 127.0.0.1:8088
      }
      handle {
          reverse_proxy 127.0.0.1:8090
      }
  }
  ```

  Порт — тот, что прошёл в 7.1. Блок `/dav` — только если владелец
  возвращает облако семьи.
- **Роутер:** проброс внешнего порта на комп, на тот же порт Caddy, TCP.
- `PRAVKA_PUBLIC_URL=https://<домен>:<порт>` — без завершающего `/`.
- **Облако семьи за той же дверью** — если владелец хочет его вернуть. Оно
  нужно для общих Денег с Марианной и ночных копий базы.
  1. rclone слушает только `127.0.0.1:8088` с `--baseurl /dav`.
  2. Папка та же, `D:\Oblako`, входы прежние: sasha, marianna, boox.
  3. На каждом телефоне: Правка → Настройки → Подключения → Облако семьи →
     домашний сервер, адрес `https://<домен>:<порт>/dav`, логин этого
     телефона, пароль.

  Приложение шлёт адрес переноса путём без хоста и понимает префикс пути
  в адресе. Проверь подключение кнопкой «Подключить» на одном телефоне.

**7.3. Запасной путь — публикует сам роутер.** Подходит, если новый роутер
умеет HTTPS со своим доменом, как KeenDNS:

- приложение роутера смотрит на комп:8090, без авторизации роутером;
- `PRAVKA_LISTEN=0.0.0.0:8090`;
- брандмауэр — 8090 только от роутера.

Проще, но при следующей смене роутера всё снова ляжет. Скажи об этом
владельцу и дай выбрать. Рекомендация облачной сессии — Caddy.

### 8. Проверка пути: Claude из облака стучится к компу

Это главный риск всего проекта. Claude ходит к MCP-серверам из облака
Anthropic в США; исходящие адреса Anthropic — `160.79.104.0/21`. Задача —
убедиться, что он доходит через провайдера, роутер и дверь из шага 7 до
компа.

1. В `D:\PravkaArchive\smoke\` заведи venv, поставь `mcp` (официальный
   Python SDK) и напиши `hello.py`:
   - `FastMCP("pravka-smoke", stateless_http=True, json_response=True, …)`,
     один инструмент `ping`. Он возвращает `pong` и текущее время компа.
   - Никаких настоящих данных, без авторизации.
   - Транспорт `streamable-http`, путь `/mcp`. Адрес и порт — те же, что в
     `PRAVKA_LISTEN`, прямо в конструктор (`host=…, port=8090`).
   - В конструктор же передай
     `transport_security=TransportSecuritySettings(enable_dns_rebinding_protection=False)`
     из `mcp.server.transport_security`. Иначе при `127.0.0.1` SDK сам
     включает проверку заголовка `Host` и отвергнет всё, что пришло через
     Caddy или роутер.
   - **Пиши в лог каждый входящий запрос** с адресом клиента и всеми
     заголовками: `Host`, `X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`
     и прочими.
2. Запусти. Проверь `curl` на `PRAVKA_PUBLIC_URL/mcp`: должен ответить
   сервер, а не страница роутера. Изнутри сети внешний адрес может не
   открыться — не все роутеры умеют петлю NAT. Тогда проверяй с телефона по
   мобильной сети.
3. Попроси владельца:
   - в claude.ai открыть Settings → Connectors → «Add custom connector»;
   - вставить адрес `PRAVKA_PUBLIC_URL/mcp`, имя «Правка проверка»;
   - в новом чате попросить «вызови ping у Правки проверки».
4. Убедись по логу, что пришли запросы из `160.79.104.0/21` (за Caddy адрес
   виден в `X-Forwarded-For`), и что Claude получил `pong`.
5. **После проверки:**
   - владелец удаляет коннектор из claude.ai;
   - ты останавливаешь `hello.py`, а папку `smoke\` удаляешь, спросив владельца.

Не прошло — разберись, на каком участке:

- есть ли ответ с компа на внутренний адрес;
- проходит ли порт снаружи (7.1);
- выдан ли сертификат (журнал Caddy);
- видит ли Claude ошибку.

Доложи владельцу словами, что именно не так. Решения в обход (туннели, VPS)
— только с его согласия.

## Часть Б — когда появится сервис

Делай, когда в ветке `pravka` репозитория `atsakunov-prog/pravka` появится
`server/README.md` с разделом «Развёртывание». Этот README — источник правды
для части Б: разошёлся с этим файлом — прав README. В общих чертах:

1. Клонировать репозиторий в `D:\PravkaArchive\repo`, ветка `pravka`.
   Репозиторий частный: войти в GitHub владельцем (`gh auth login` или
   менеджер учётных данных Git).
2. venv в `D:\PravkaArchive\repo\server\.venv`, затем
   `pip install -r requirements.txt`.
3. Применить схему: `python -m pravka_archive migrate`.
4. Самопроверка: `python -m pravka_archive check` (база, роли, папки, адрес).
5. Задача планировщика «Pravka Archive» от SYSTEM:
   - при старте системы — `python -m pravka_archive serve`;
   - перезапуск при сбое;
   - лог — в `logs\`.
6. Подключить в claude.ai коннектор «Правка» с адресом `PRAVKA_PUBLIC_URL/mcp`.
   Вход — страница сервиса, пароль `PRAVKA_OWNER_PASSWORD`.
7. Токен и адрес для телефона: сервис покажет их QR-кодом. Как именно —
   написано в README.

Обновление в будущем: `git pull` в `repo`, `migrate`, перезапуск задачи.
