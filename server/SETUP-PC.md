# Задача для Claude Code на домашнем компе: каркас архива Правки

Ты работаешь на домашнем компе владельца (Саша). Это Windows, включён
всегда, у роутера постоянный внешний IP. Говори с владельцем по-русски, живо и
коротко, без канцелярита.

## Что строим и зачем

Правка — личное Android-приложение владельца: таймшит (Засечка), деньги, спорт,
еда, диктовка. Сейчас его данные живут на телефоне, и телефон их забывает:
тексты диктовок ротируются, еда хранится 420 дней, тренировки 120. Строим
**архив на этом компе**:

- PostgreSQL на диске D:, в нём журнал событий, который только дописывается;
- сервис на Python (код — в репозитории, папка `server/`, его пишет облачная
  сессия), а в нём три части:
  - приёмник событий с телефона: `POST /ingest` с токеном;
  - сборщик intervals.icu: забирает тренировки и wellness напрямую;
  - MCP-сервер для claude.ai: `/mcp`, вход по OAuth. Через него Claude отвечает
    на вопросы владельца о его жизни.

## Сеть: что известно на 01.10.2026

- **Роутер — Netcraze** (это Keenetic под российским именем).
  - Служба CrazeDNS (аналог KeenDNS): домен `znakomiy.netcraze.pro`, с
    сертификатом.
  - Режим «Direct access» — значит, внешний адрес публичный.
  - «Allow access from the Internet» включено, IPv6 выключен.
- **Комп в сети — `192.168.1.77`.**
- **В CrazeDNS уже заведены два веб-приложения**, оба в «Remote access: No
  access», то есть снаружи закрыты:
  - `vpn.znakomiy.netcraze.pro` смотрит на 192.168.1.77:8090 по HTTP;
  - `server.znakomiy.netcraze.pro` смотрит на 192.168.1.77:8443 по HTTP.
- **Прежний роутер был тоже Netcraze**, с доменом `pravka.netcraze.pro`.
  - Облако семьи (`rclone serve webdav` папки `D:\Oblako` на порту 8088,
    задачей планировщика от SYSTEM) было снаружи на
    `https://webdav.pravka.netcraze.pro:8443`.
  - Порт 8443 — потому что 443 провайдер (Билайн) резал до роутера,
    проверено 26.09.
  - С новым роутером эта публикация пропала. Общие Деньги с Марианной не
    синхронизируются, ночные копии базы не доезжают, книги Слушалки не
    качаются. Данные не теряются: журналы и копии ждут на телефонах.

Публикуем так же, как прежде: **приложениями CrazeDNS роутера**. У роутера
свой домен и сертификат, ставить на комп ничего не нужно. Запасной путь (Caddy
на компе) — в конце шага 7, на случай если роутер подведёт.

Эта задача делится на две части:

- **Часть А — подготовить машину, вернуть облако семьи, проверить путь
  Claude до компа.** Её делаешь сейчас.
- **Часть Б — развернуть сервис из репозитория.** В ветке `pravka` уже лежит
  `server/README.md` с разделом «Развёртывание». Переходи к нему сразу после
  части А.

## Чего нельзя

- **Не трогать файлы `D:\Oblako`.** Задачу rclone меняй только ради того,
  чтобы вернуть облако семьи (шаг 7), и только с согласия владельца.
- **Архив не класть внутрь `D:\Oblako`.** Эту папку видят по WebDAV все
  устройства семьи, а в архиве личные диктовки и деньги.
- **Postgres слушает только `127.0.0.1`.** Базу в сеть не выставлять никогда.
- **Секреты** (пароли, токены, ключ intervals):
  - живут только в `D:\PravkaArchive\secrets\`;
  - в репозиторий не попадают;
  - в чат целиком не выводятся: показывай первые 4 знака.
- **Перед необратимым — спросить владельца.** Это удаление, форматирование,
  перезапись чужих файлов, смена настроек роутера.
- **Роутер ты не настраиваешь.** Это делает владелец руками в веб-интерфейсе
  Netcraze, ты ведёшь по шагам и проверяешь результат.

## Часть А

### 1. Осмотреться и доложить

Прежде чем ставить что-либо, собери и покажи владельцу:

- **система:** версия Windows и наличие `winget`;
- **диски** (`Get-PhysicalDisk`, `Get-Partition`, `Get-Volume`):
  - лежат ли C: и D: на **разных физических дисках**;
  - сколько свободно на каждом.

  От этого зависит, защищает ли ночная копия от смерти диска.
- **что уже стоит:** Git, Python, PostgreSQL (версии);
- **адреса:** что адрес компа действительно `192.168.1.77`, и адрес роутера
  (шлюз);
- **внешний адрес.** Сравни `Invoke-RestMethod https://api.ipify.org` с внешним
  (WAN) адресом в роутере. Должны совпасть: так говорит «Direct access»;
- **что слушает на 8090, 8443 и 8088.** `Get-NetTCPConnection -State Listen`
  с процессом. Ни 8090, ни 8443 не должны быть заняты чем-то, что ты сломаешь:
  на них уже смотрят приложения `vpn` и `server`;
- **rclone:**
  - есть ли его задача планировщика, работает ли, с какими аргументами;
  - где лежит файл входов (htpasswd с sasha, marianna, boox).

  С неё же берём образец, как запускать службы.

### 2. Папки

```
D:\PravkaArchive\
  pgdata\    данные PostgreSQL
  blobs\     файлы: фото тарелок, выписки банков, звук диктовок
  backups\   ночные копии базы
  secrets\   server.env и пароли
  logs\      журналы сервиса
  repo\      клон репозитория (часть Б)
  smoke\     временный проверочный сервер (удалить после проверки)
```

На `secrets\` сними наследование прав и оставь доступ только SYSTEM,
Администраторам и учётной записи владельца (`icacls`).

### 3. Поставить

- **Git** — если нет.
- **Python 3.12 или новее** (`winget`) — для всех пользователей, с `py`-лаунчером.
- **PostgreSQL 16 или новее** (`winget` или установщик EDB):
  - каталог данных — `D:\PravkaArchive\pgdata`;
  - служба с автозапуском;
  - `listen_addresses = '127.0.0.1'`;
  - пароль суперпользователя `postgres` — в `secrets\postgres.txt`.

### 4. База и роли

От суперпользователя:

```sql
CREATE ROLE pravka LOGIN PASSWORD '<сгенерировать>';
CREATE DATABASE pravka OWNER pravka ENCODING 'UTF8' TEMPLATE template0;
CREATE ROLE pravka_reader LOGIN PASSWORD '<сгенерировать>';
ALTER ROLE pravka_reader SET default_transaction_read_only = on;
ALTER ROLE pravka_reader SET statement_timeout = '15s';
GRANT CONNECT ON DATABASE pravka TO pravka_reader;
```

Таблицы, виды и права на чтение создаёт сам сервис командой `migrate` в
части Б. Сейчас их не заводи.

Проверь, что входишь обеими ролями через `psql -h 127.0.0.1`.

### 5. Файл секретов

`D:\PravkaArchive\secrets\server.env` — строки `ИМЯ=значение`, без кавычек:

```
PRAVKA_DB_URL=postgresql://pravka:<пароль>@127.0.0.1:5432/pravka
PRAVKA_DB_READER_URL=postgresql://pravka_reader:<пароль>@127.0.0.1:5432/pravka
PRAVKA_LISTEN=0.0.0.0:8090
PRAVKA_PUBLIC_URL=
PRAVKA_INGEST_TOKEN=<64 случайных hex-знака>
PRAVKA_OWNER_PASSWORD=<см. ниже>
PRAVKA_BLOBS=D:\PravkaArchive\blobs
PRAVKA_LOGS=D:\PravkaArchive\logs
ICU_ATHLETE_ID=
ICU_API_KEY=
```

- **`PRAVKA_INGEST_TOKEN`** — по нему телефон доказывает, что он телефон.
  Сгенерируй криптостойко: `RandomNumberGenerator`, не `Get-Random`.
- **`PRAVKA_OWNER_PASSWORD`** — пароль, который владелец один раз введёт на
  странице входа, когда подключит архив в claude.ai.
  - Спроси, хочет ли он свой. Если нет — сгенерируй пять случайных русских
    слов через дефис: такое легко набрать на телефоне.
  - Покажи пароль владельцу один раз и попроси сохранить.
- **`PRAVKA_LISTEN`.** Порт 8090, если на шаге 1 он свободен или занят
  заготовкой под архив. Иначе — свободный рядом, и приложение роутера
  смотрит на него.
- **`PRAVKA_PUBLIC_URL`** заполнишь в шаге 7.
- **`ICU_ATHLETE_ID` и `ICU_API_KEY`** вставляет владелец. В intervals.icu это
  Settings, раздел Developer Settings: там API key и Athlete ID вида `i12345`.
  Подскажи, где это. Если ключа пока нет, оставь пустым: сборщик intervals
  просто не запустится.

### 6. Брандмауэр

Роутер пересылает запросы под своим адресом. Поэтому правила такие:

- входящее TCP на порт архива (8090) и rclone (8088);
- удалённый адрес — **только роутер** (шлюз из шага 1);
- профиль «Частная».

Больше никто из локальной сети стучаться в них не должен.

### 7. Публикация наружу — владелец в роутере, ты ведёшь

**7.1. Решить, что куда смотрит.** Покажи владельцу, что на шаге 1 нашлось на
8090 и 8443, и спроси, что он задумывал под `vpn` и `server`. Не ломай то,
что там уже работает. Рекомендация облачной сессии:

| Приложение CrazeDNS | Куда | Зачем |
|---|---|---|
| `archive` | 192.168.1.77:8090, HTTP | архив: Claude и телефон |
| `webdav` | 192.168.1.77:8088, HTTP | облако семьи (rclone) |

Если `vpn` — заготовка под архив на тот же 8090, перенастрой её или
переименуй, а не заводи вторую на тот же порт. Пустые лишние приложения
предложи удалить. Имя `webdav` — то же, что было на прежнем роутере: так
владельцу легче узнать его на телефонах.

**7.2. Доступ.** У обоих приложений «Remote access» сейчас «No access».
Нужно разрешить доступ из интернета **без авторизации роутером**. Claude и
телефоны в роутер входить не умеют, вход проверяют сами сервисы:

- у архива — OAuth для Claude и токен для телефона;
- у rclone — свои логины.

**7.3. Внешний порт.** Прежнее облако жило на `:8443`, потому что 443 резал
Билайн.

- Проверь оба адреса **с телефона по мобильной сети**, не по домашнему Wi-Fi:
  `https://archive.znakomiy.netcraze.pro/health` и
  `https://archive.znakomiy.netcraze.pro:8443/health`. Изнутри сети внешний
  адрес может не открыться: не у всех роутеров есть петля NAT.
- Проходит 443 — порт в адресе не нужен.
- Не проходит — найди с владельцем в настройках Netcraze, как на прежнем
  роутере был включён доступ на 8443 (порт HTTPS для удалённого доступа), и
  включи так же.

Пока сервиса ещё нет, на `/health` для проверки отвечает пробный сервер из
шага 8. Этот шаг можно делать вместе с ним.

**7.4. Записать адрес** без завершающего `/`:
`PRAVKA_PUBLIC_URL=https://archive.znakomiy.netcraze.pro` (или с `:8443`).

**7.5. Вернуть облако семьи.**

1. Если задача rclone и файл входов целы — проверь, что rclone слушает
   `0.0.0.0:8088`, и запусти.
2. Если снесены — заведи заново: `rclone serve webdav D:\Oblako --addr
   0.0.0.0:8088 --htpasswd <файл>`, задачей от SYSTEM при старте, с
   перезапуском. Входы — sasha, marianna, boox.
   - Если старых хешей нет, создай новые пароли и покажи их владельцу один
     раз.
3. Проверь снаружи: `PROPFIND` на `https://webdav.znakomiy.netcraze.pro[:порт]/`
   с логином отвечает `207`. Ответ `200` со страницей — это роутер, а не rclone.
4. Скажи владельцу, где поменять адрес на
   `https://webdav.znakomiy.netcraze.pro[:порт]` — на телефонах Саши,
   Марианны и Boox:
   - Правка: Настройки → Подключения → Облако семьи → домашний сервер (адрес,
     логин этого телефона, пароль), затем «Подключить»;
   - Слушалка: её WebDAV для книг (была настроена на
     `webdav.pravka.netcraze.pro:8443`, логин sasha).

**7.6. Запасной путь — Caddy на компе.** Только если публикация роутером не
заработает или владелец захочет не зависеть от роутера:

- Caddy с сертификатом Let's Encrypt через DNS-проверку (сборка с модулем
  DNS на caddyserver.com/download);
- роутер только пробрасывает один порт;
- за Caddy архив на `127.0.0.1:8090` и rclone на `127.0.0.1:8088` под `/dav`.

Сервис к этому готов: заголовок `Host` он не проверяет.

### 8. Проверка пути: Claude из облака стучится к компу

> **01.10.2026: этот шаг можно пропустить.** Авто-режим Claude Code не даёт
> поднять наружу пробный MCP без входа («Expose Local Services»), и он прав.
> Настоящий сервис уже готов, и вход у него закрыт OAuth. Поэтому проверкой
> пути станет его первое подключение в claude.ai (часть Б, README, шаг 5).
> Ниже — как было задумано, на случай если пригодится разбирать путь по
> кускам.

Это главный риск всего проекта. Claude ходит к MCP-серверам из облака
Anthropic в США; исходящие адреса Anthropic — `160.79.104.0/21`. Задача —
убедиться, что он доходит через провайдера и CrazeDNS до компа.

1. В `D:\PravkaArchive\smoke\` заведи venv, поставь `mcp` (официальный
   Python SDK) и напиши `hello.py`:
   - `FastMCP("pravka-smoke", stateless_http=True, json_response=True, …)`,
     один инструмент `ping`. Он возвращает `pong` и текущее время компа.
   - Плюс маршрут `/health`, отвечающий `ok`.
   - Никаких настоящих данных, без авторизации.
   - Транспорт `streamable-http`, путь `/mcp`. Адрес и порт — из
     `PRAVKA_LISTEN`, прямо в конструктор (`host="0.0.0.0", port=8090`).
   - В конструктор же передай
     `transport_security=TransportSecuritySettings(enable_dns_rebinding_protection=False)`
     из `mcp.server.transport_security`. Иначе SDK может отвергнуть чужой
     заголовок `Host`: роутер подставляет свой.
   - **Пиши в лог каждый входящий запрос** с адресом клиента и всеми
     заголовками: `Host`, `X-Forwarded-For`, `X-Real-IP`, `X-Forwarded-Proto`
     и прочими.
2. Запусти и проверь `/health` по внешнему адресу (7.3).
3. Попроси владельца:
   - в claude.ai открыть Settings → Connectors → «Add custom connector»;
   - вставить адрес `PRAVKA_PUBLIC_URL/mcp`, имя «Правка проверка»;
   - в новом чате попросить «вызови ping у Правки проверки».
4. Убедись по логу, что запросы пришли. Адрес Anthropic `160.79.104.0/21`
   будет в `X-Forwarded-For` или `X-Real-IP`, если роутер их ставит. Если не
   ставит — запиши, что видно. Claude должен был получить `pong`.
5. **После проверки:**
   - владелец удаляет коннектор из claude.ai;
   - ты останавливаешь `hello.py`, а папку `smoke\` удаляешь, спросив владельца.

Не прошло — разберись, на каком участке:

- есть ли ответ с компа на `192.168.1.77:8090`;
- проходит ли внешний порт (7.3);
- открыт ли доступ у приложения (7.2);
- видит ли Claude ошибку.

Доложи владельцу словами, что именно не так. Решения в обход (туннели, VPS)
— только с его согласия.

- хранить 14 последних дней и первую копию каждого месяца за год, остальное
  удалять;
- журнал копии писать в `logs\`.

Если C: — **другой физический диск** и на нём хватает места, свежую копию
держи и там: `C:\PravkaArchiveCopy\`, только последние 3. Если диск один,
так и скажи владельцу: ночная копия на том же диске спасает от ошибки, но не
от смерти диска.

Копию наружу (в другое место за пределами дома) владелец ещё не выбрал.
Спроси его и, если выберет, предложи способ с шифрованием. Не выбрал — оставь
пунктом в отчёте.

## Часть Б — развернуть сервис

Источник правды — `server/README.md`, раздел «Развёртывание». Разошёлся с
этим файлом — прав README. Установку делает скрипт
`server\windows\install.ps1`, его владелец запускает сам от администратора:
задачи планировщика и правила брандмауэра авто-режим Claude Code не
регистрирует. Твоё дело — довести до скрипта и разобрать его итог
(`logs\install-<дата>.log`). В общих чертах:

1. Клонировать репозиторий в `D:\PravkaArchive\repo`, ветка `pravka`.
   Репозиторий частный: войти в GitHub владельцем (`gh auth login` или
   менеджер учётных данных Git). Если репозиторий уже склонирован в другое
   место — склонируй ещё раз сюда: служба работает из `D:\PravkaArchive\repo`.
2. venv в `D:\PravkaArchive\repo\server\.venv`, затем
   `pip install -r requirements.txt`.
3. Применить схему: `python -m pravka_archive migrate`.
4. Самопроверка: `python -m pravka_archive check` (база, роли, папки, адрес).
5. Задача планировщика «Pravka Archive» от SYSTEM:
   - при старте системы — `python -m pravka_archive serve`;
   - перезапуск при сбое;
   - лог — в `logs\`.
6. Подключить в claude.ai коннектор «Правка» с адресом `PRAVKA_PUBLIC_URL/mcp`.
   Вход — страница сервиса, пароль `PRAVKA_OWNER_PASSWORD`.
7. Токен и адрес для телефона: сервис покажет их QR-кодом. Как именно —
   написано в README.

Обновление в будущем: `git pull` в `repo`, `migrate`, перезапуск задачи.
