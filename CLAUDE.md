# Слушалка — карта для сессии

Плеер аудиокниг с читалкой и вопросами по книге: Kotlin, Compose, Media3, один
APK `ru.zf.slushalka`. Живёт в ветке **`slushalka`** репозитория Pravka; с
Правкой (ветка `pravka`) общие только `keystore/pravka.jks` и ветка
`apk-builds`. Код и документация — по-русски, комментарии объясняют ПОЧЕМУ.
Спецификация — `README.md`; здесь только карта.

## Где что

- `slushalka/src/main/java/ru/zf/slushalka/`
  - `SlushalkaApp.kt` — сервис-локатор; `MainActivity.kt` — экраны.
  - `player/` — Media3, служба воспроизведения, «за 15 минут» разбора —
    свой маленький `ClipPlayer` мимо плеера книги, шторка (в развёрнутой —
    «Спросить голосом»: `Shade.ACTION_VOICE_ASK`, его же зовёт микрофон на
    виджете; `AskSheet(handsFree)` слушает сразу, отправляет сам, отвечает
    вслух), куски аудио. Служба
    поднимается на каждом пуске звука (`PlayerHolder.ensureService`), не
    только при открытии книги: иначе после её остановки звук идёт без шторки.
  - `library/` — сканер папки SAF, книги, естественный порядок файлов. Папка с
    одним текстом и без подпапок — книга **без звука** (`Book.hasAudio`): её
    открывают читалкой, минуя плеер и карту «звук ↔ текст». Папок несколько:
    главная (`Prefs.libraryUri`, туда качает каталог и там `_Слушалка`) и
    дополнительные (`Prefs.libraryExtra`); каждая книга помнит своё дерево
    (`Book.tree`), файлы книги брать через `AppState.treeOf(book)`, а не
    `treeUri()` (это главная).
  - `catalog/` — Флибуста по OPDS: `Opds.kt` (разбор Atom-ленты),
    `FlibustaClient.kt` (сеть, адрес из настроек, повтор на 503),
    `SmartSearch.kt` (запрос → варианты написания, авторы несколькими быстрыми
    запросами, книги одним медленным, ранжирование), `CatalogState.kt` (стопка
    лент, поиск в два такта, кэш лент и подгрузка следующей страницы заранее,
    скачивание книги своей папкой `<Автор> - <Название>/` в корень библиотеки
    и перечитывание папки), `Advisor.kt` (советник на модели: контекст по
    месту — полка, автор, книга; строка «ИСКАТЬ:» в ответе → кнопки поиска;
    web_search через `ClaudeClient.chat`). Библиотека договорена жить в
    `Downloads/Books`; пикер открывается в Downloads.
  - `speech/` — всё, что про голос, но не про Claude: озвучка книги без записи
    системным TTS — `ReadAloud.kt` (куски, очередь движка, пауза по фразе,
    фокус звука), `ReadAloudService.kt` (передний план, уведомление); голосовой
    ввод `VoiceInput.kt`, ответ вслух `Speaker.kt`, распознавание куска аудио
    для карты «звук ↔ текст» `ChunkRecognizer.kt`. Вход озвучки — «Озвучить» в
    читалке, голос и темп — настройки, раздел «Озвучка». Оба синтезатора
    (`ReadAloud`, `Speaker`) заводятся по требованию и отпускаются тишиной:
    на старте приложения TTS не поднимать — он держит службу речи Google
    живой, пока жив процесс (батарея, 01.10.2026).
  - Устройство — `Prefs.readerDevice` (телефон / читалка цветная / читалка
    простая; `readerEink` — любая электронная бумага, `readerEinkLow` —
    простая): `Prefs.readerView()` подменяет вид читалки (простая: плоско,
    страницами, крупнее, чистые белый/чёрный, без анимаций; цветная: книга
    как есть, без загиба, растворения, зерна и прокрутки), сохранённое не
    трогает; `EinkDevice.likely` — заводское «простая» на электронных книгах;
    тема приложения — `SlushalkaTheme(eink = readerEinkLow)`; плашки —
    `LocalEink` (любая); кнопки листания — `PageKeys` (ловит
    `MainActivity.dispatchKeyEvent`, громкость — только когда тихо).
  - `res/font/` — Literata, PT Serif, PT Sans, Lora, Merriweather, Bitter
    (все SIL OFL, `assets/fonts-OFL.txt`; урезать можно только Literata и
    Bitter — у остальных зарезервированное имя), список — `Settings.FONTS`.
    Literata (SIL OFL): книжная антиква своей гарнитурой,
    системная «с засечками» на разных прошивках разная. Заводской шрифт
    читалки; типографика (поля по канону, висячие строки, капитель, типограф,
    неровности) — тумблерами в «Набор», все разом — кнопкой «Набрать как
    книгу» (`Settings.setBookTypography`).
  - `text/` — fb2/epub, текст книги, привязка «секунда ↔ знак»
    (`Alignment.kt`, `Locator.kt`), извлечение текста.
  - `ask/` — Claude: `Models.kt` (единый список моделей: id, имя, цена,
    «усилие по умолчанию»; `Settings.MODEL_*` — ссылки на него),
    `ClaudeClient.kt` (транспорт, расчёт цены, Message Batches),
    `AskEngine.kt` (вопрос по книге: объём `Scope`, кэш, спойлеры, разговор
    репликами; пересказ), `Prompts.kt`, `Guide.kt` + `GuideEngine.kt`
    (справочник по книге: содержание глав, герои, места, словарь по главам;
    заказ пакетом, опрос, починка обрезанного JSON, склейка частей; состояние
    — `data/GuideStore.kt`, готовый — ещё и файлом `слушалка-справочник.json` в
    папке книги, оттуда же подхватывается чужой; связи героев `GuideLink` и
    хронология `GuideEvent` — каждая с главой, где открывается; старый
    справочник без них — `Guide.isOld`), `MeaningSearch.kt` (поиск по смыслу:
    сперва по справочнику `Guide.asText`, место в главе — по приметам даром,
    иначе одна глава модели; по тексту — отдельной кнопкой с ценой),
    `BookTalk.kt` (разговор о книге: темы, реплики; контекст — справочник и
    кусок текста, дочитанную — без барьера), разбор книги сервером —
    `Razbor.kt` (формат `слушалка-разбор.json`: карточка, главы с `before`,
    `summary15`, идеи, линзы в общий вид `LensItem`, ссылки `RazborRef` с
    `at(text)`) и `RazborEngine.kt` (чтение с сервера с копией
    `data/RazborStore.kt`, заказ — `слушалка-разбор.заказ.json`, статус пишет
    сервер, слежение раз в минуту, на «готово» — перечитать разбор и
    справочник; цена — `estimateUsd`); справочник разбора сервера
    (`GuideState.fromServer`) побеждает свой, если новее и подходит к тексту
    (`GuideEngine.sync`/`serverGuide`), линзы на выделенном —
    `Prompts.CRAFT/MOTIVES/FOR_KID`, пересказ для ребёнка —
    `RECAP_KIDS_RULES`, конспект пометок — `AskEngine.digest` +
    `Prompts.DIGEST_RULES`.
  - `data/` — `Settings.kt` (DataStore снимком `Prefs`, в том числе модели и
    усилие для вопроса и пересказа, масштаб интерфейса `uiScale` — множитель
    к `LocalDensity` в `MainActivity`), позиции и их синк (`PositionSync.kt`:
    в главной папке `_Слушалка/позиции-<имя>.json` с секундой и знаком
    чтения, с 03.10 ещё `места-<имя>@<устройство>.json` — у каждой книги два
    места, `listen` и `read`, каждое со своим временем (`BookState.listenAt/
    readAt`), один писатель на файл, слияние по каждому месту —
    `mergeStates`; открывается место, тронутое последним
    (`AppState.readingStart`, `followLaterReading`); плеер пишет место, только
    если звук шёл или его двигали рукой (`PlayerHolder.heard`), откат — на
    пуске, не на открытии; своё место с другого устройства берётся молча,
    строкой `MovedBar` с «Вернуть»; места личные — качаются только свои
    файлы (`PositionSync.isMine`), чужие не показываются нигде; `вопросы-<имя>.json` — история вопросов, сливается по времени;
    транспорт между устройствами — сторонняя синхронизация папки или облако
    по WebDAV: `Cloud.kt` — клиент (PROPFIND/GET/PUT/MKCOL/MOVE, `stat`,
    запись через `.partial` + MOVE — `putTextAtomic`/`uploadAtomic`;
    `Destination` — путь от корня сервера, на 502 — полный адрес, рабочая
    форма помнится (`Cloud.moveVia`); MOVE не прошёл — текст PUT в конечное
    имя и DELETE `.partial`, книги и звук — ошибка;
    Яндекс.Диск с паролем приложения; папка `/` — корень сервера,
    `Prefs.cloudAtRoot`), те же файлы в `<папка>/_Слушалка`, тела собирает
    companion `PositionSync`; книги в облаке — `CloudBooks.kt`, папки в
    `<папка>/Книги`, скачать на полку и выгрузить с неё (у домашней
    библиотеки — в корень сервера, его разложит сортировщик), экран
    `CloudScreen`), разметка.
  - Озвучка нейросетью на сервере — `data/NightVoice.kt`: заказ
    `слушалка-озвучка.заказ.json` (статусы сервера, `limit` — его проверка,
    не показывать; свежесть 6 ч от `at`), прикидка `estimate`, `canOrder` —
    у сервера текст без звука и своего звука нет; кнопка — `VoiceOrderBlock`
    в карточке книги; пометка — `озвучка.json` в `other`
    (`ServerBook.machineVoiced`): карточка, плеер, строка формата. Своя копия
    без звука берёт звук сервера потоком (`AppState.withServerAudio`, его же
    зовёт `MainActivity.openBook` до выбора экрана).
  - Библиотека на сервере — `data/ServerLibrary.kt`: `index.json` в корне
    облака (один GET, копия на диске, `refreshIfStale`), обложки в
    `cache/server-covers`, `toBook` — книга сервера с ключом
    `<имя главной папки>/<папка>`, как после скачивания. В `AppState` —
    `serverBooks`, `bookById` (полка, потом сервер), `deleteFromPhone`. У
    файла книги источник: `BookFile.remote` (путь от корня облака) или
    `docId`; у книги — `remoteDir`, `textRemote`, `coverRemote`,
    `hasText`/`onPhone`/`streams`. **Полка одна** (05.10, владелец: «одна
    правда на сервере») — книги `index.json` плюс книги телефона, которых
    там нет; переключателя нет. Своя папка — копия книги сервера под её
    ключом (`library/OneShelf.kt`: псевдоним сверки → то же имя без регистра

    сервера); `Book.phoneId`/`phoneKey`/`phoneFolder` — своя папка, только

    диске — они) → `readopt()` → `books` + `adopted()` (главные, лишние
    копии, `keyOf`), `canonicalOf` — ключ для мест/вопросов/пометок с
    других устройств, `start()` — из конца `onCreate`. Сверка —
    `data/ShelfSync.kt`: `полка-<имя>@<устр>.json` (запуск, перемены, не
    чаще 10 мин, `checkNow`), ответ `сверка-…json` (`shelf_at` — на какую

    долгое — окно `BookSheet` (скачать, удалить копию). Серия — `Book.series/seriesNum` (null — не

    поверх порядка — `Prefs.shelfGroup` (серии / авторы / без групп),

    поиск `matchesShelfQuery`), меню — `SortButton`; поиск по полке —
    `ShelfSearch` над «Продолжить», Флибуста — глобус в шапке. На полке — `SeriesLink` (фильтр), плашка

    на слое слота (слои «ранний сверху», `zIndex(-slot)`; сгиб пришит к
    корешку), `Modifier.curlDrag` ведёт пейджер сам (`userScrollEnabled =
    false`, `dispatchRawDelta` с пересчётом пути); изнанка листа — снимок
    слоя просвета той же страницы (`PageFace.onBackLayer` →
    `CurlState.setBack`, второй вход шейдера `back`). На половине разворота
    гнётся правая страница при переходе на следующую левую (`leafTurn`),
    остальное — переезд камеры (`halfPan(hideTurned)`). Три прежних
    переворота-«картона» владелец забраковал. Где загиба нет (e-ink,
    старый Android, шейдер не принят) — страница **растворяется**;
    `readerPageTurn` относится к карточкам.
    На узком экране — половина разворота (`BookShape.half`, `halfPan`,
    подглядывание `BOOK_PEEK`: камера ездит по развороту), при «всегда одна» —
    книга целиком в экране. Полоса набора сидит на сетке строк, а остаток
    места страница раздаёт воздуху у заголовка (`Page.slack`) — иначе перед
    невлезшей главой зияет дыра; вверху колонтитул: на левой странице автор
    и название, на правой глава (тап — содержание), на единственной обе
    (`HeadRow` даёт главе до половины строки), внизу номер со всем объёмом у
    наружного края. «Обрез снизу» (`Prefs.readerBookTilt`, `PageLook.tilt`,
    `CardMetrics.foot`): торец блока под страницами веером к корешку;
    книга в безопасной области, сверху прижата к часам (`CardMetrics.top =
    0`); значки панелей под стол — `WindowCompat` в `ReaderScreen`; «Ляссе»
    (`Prefs.readerBookRibbon`,
    `drawRibbon`). Изнанки для загиба снимаются заранее (`backCache`); валик
    — конус к корешку (uniform `cone`); вздрагивания при посадке нет; неровности
    печати — ещё и по словам в `litText(press)` плюс зерно поверх букв
    (`PageLook.press`). **Просвет с
    оборота** (`PageLook.bleed`, `Prefs.readerBleed/readerBleedLevel`):
    под текстом страницы зеркально и размыто набрана та, что на обороте
    листа (у левой предыдущая, у правой и единственной следующая), тем же
    `PageColumn(ghost = true)` без картинок, реестра попаданий и краски.
    Переплёт: на кант ложатся края обложки — `CoverEdges`/`coverEdges()`
    в `Covers.kt`, левая крышка отражена; тень на стол — размытый
    `GraphicsLayer` (Android 12+, ниже слоями); облачность бумаги — под
    матовостью.
    Поле от
    края, тень, стол, фаска, блик, матовость, колонтитулы и переносы —
    каждое своим тумблером (`PageLook`)),
    разбор (`RazborSheet.kt`: вкладки, без спойлер-барьера — «Главы»
    открываются на своей, «ты здесь»; «К месту» — `onGo`, заказ —
    `RazborOrderPanel`, его же показывает справочник; «что было раньше» —
    карточкой вместо «Напомнить?» в читалке и плеере, вход с полки —
    `AppState.requestRazbor`),
    вопрос (`AskSheet.kt`: модель,
    ползунок объёма, кэш, спойлеры, цена, уточнения), пересказ (`RecapSheet.kt`,
    кнопка «Напомнить»), справочник (`GuideSheet.kt`), листы читалки
    (`ReaderSheets.kt`: «Содержание» по главам и «Этот кусок» по долгому
    нажатию на абзац или по обводке пальцем — `Lasso.kt`: реестр границ и
    раскладки абзацев `TextHits`, по нему же тап в прокрутке листает ровно на
    страницу по строкам, слой росчерка `LassoLayer`), настройки, каталог Флибусты (`CatalogScreen.kt`, вход —
    глобус с лупой над полкой), лист советника (`AdvisorSheet.kt`) и статистика
    (`StatsScreen.kt`, вход — столбики на полке; графики рисуются `Canvas`,
    тап по столбику — подробности).

## Сборка и проверка

```bash
./gradlew :slushalka:compileReleaseKotlin -PbuildNumber=999   # компиляция
./gradlew :slushalka:assembleRelease -PbuildNumber=999         # APK
```

В облачной сессии SDK ставится в `/opt/android-sdk`, путь — в
`local.properties` (`sdk.dir=…`, файл не в git). Перед пушем компиляция
обязательна.

## Ветка и доставка

- **В репозитории две ветки: `slushalka` и `pravka`** (плюс служебная
  `apk-builds`, куда пишет только CI). Работа Слушалки коммитится и пушится
  **прямо в `slushalka`**, никаких рабочих веток `claude/...` в origin:
  если сессия открыта на такой ветке, работу переносить в `slushalka`
  fast-forward'ом, ветку удалять. Другие ветки не создавать, PR не открывать
  без явной просьбы. Коммиты: тема по-русски, дальше причины.
- CI (`.github/workflows/build-apk.yml`) собирает релизный APK на каждый пуш,
  а публикует в `apk-builds` **только из `slushalka`**: `slushalka.apk`,
  `slushalka-build-info.txt` (+ `slushalka-debug.apk` для старых копий). Файлы
  Правки рядом (`pravka-debug.apk`, `build-info.txt`) не трогать: публикация
  забирает их из ветки и кладёт обратно, пуш — с `--force-with-lease` и
  повтором.
- Приложение читает `slushalka-build-info.txt`; файл без строки `slushalka=` —
  не его сборка, и перед установкой проверяется пакет внутри APK.
- Подпись — только `keystore/pravka.jks`. Другой ключ сломает установку
  поверх и стёр бы позиции и разметку.
- Модели и усилие для вопроса, пересказа, справочника и советника — настройки
  владельца (`Settings.Prefs.askModel/recapModel/guideModel/adviseModel`,
  раздел «Модели»), заводская везде — Опус 5.5 (`claude-opus-5-5`; его
  «по умолчанию» — явный `high`, `Settings.defaultEffort`: у API для него
  medium; ключи моделей в DataStore с суффиксом `_55`); модель,
  объём (`askScope`) и кэш (`askCache`) вопроса меняются и в самом окне. В
  запросе `thinking` не передаётся (Fable и Опус 5.5 отвергают «disabled»). `ClaudeClient`
  — свой транспорт на OkHttp (стрим, кэш на час, `web_search`, `stop_reason:
  refusal`, `/v1/messages/batches` для справочника), без SDK.
