# Правка — карта для сессии

Личное Android-приложение одного владельца: Kotlin, Compose, один APK. Диктовка в
любое поле (Правка), таймшит (Засечка), дела в Todoist (Дела и Разноска), спорт
и еда (Тело). Один движок слушает все диктовки и ходит в Claude; режимы живут
вокруг него. Код и документация — по-русски, комментарии объясняют ПОЧЕМУ.

## Как читать репозиторий (это главное)

Не читай README и код целиком. Сессия на «одну кнопку» должна прочитать ОДИН
документ режима и файлы из его раздела «Файлы режима» — обычно три-пять.

| Задача касается | Прочитать сначала |
|---|---|
| Правка текста, кнопка «П», словарь, правила, обучение, эвалы, ночной разбор, правка промпта («Ещё → Разборы») | `docs/pravka.md` |
| Засечка: лента, категории, телефон по дням, автопилот, NFC, Sheets, напоминания | `docs/zasechka.md` |
| Дела и Разноска: Todoist, кнопка «Д» | `docs/dela.md` |
| Тело: план дня, силовые, зарядка, светофор, intervals, Notion (план, справочник, Дневник) | `docs/telo.md` |
| Еда: КБЖУ, витамины и элементы, таблетки, дневник, рацион, wellness | `docs/eda.md` |
| Разборы: структура и синк жизни в Notion, книга Excel «Вся жизнь» (поиск паттернов снят) | `docs/razbory.md` |
| Общая статистика (бывший Отчёт): день в графиках, тот же день неделю назад, коэффициенты; выгрузка книги — значком в её шапке | `docs/otchet.md` |
| Шапка вкладки (статистика, доллар, шестерёнка), фон и плашки, страницы поверх вкладок | `ui/Frame.kt`, `MainActivity.kt`, раздел «Каркас экрана» в `docs/agreements.md` |
| Служба, плавающие кнопки, самообновление, настройки, хранение | `docs/build.md`, `docs/data.md`, раздел «Движок» ниже |
| Деление на модули, что где лежит и почему | `docs/architecture.md` |

Перед правкой ленты (`ZasechkaStore`), службы доступности, промптов или любой
записи в Notion и intervals — открой `docs/agreements.md`: там причины, по
которым код такой, какой есть, с реальными случаями. Ниже — только выжимка.

## Движок (общее для всех режимов, читать по необходимости)

- **Диктовка:** `provider/GoogleSpeechSession.kt`, `provider/WhisperProvider.kt`
  (+ `WhisperNative.kt`), `data/Recordings.kt`, `data/WavFile.kt`,
  `data/LiveDraft.kt`, `trigger/DictationService.kt`, `core/VoiceCommands.kt`.
  Пока микрофон наш, экран не гаснет: `DictationService` зовёт
  `PravkaAccessibilityService.keepScreenOn` (окно 1×1 с `FLAG_KEEP_SCREEN_ON`).
  Тикер диктовки — бегущая строка `trigger/MarqueeTickerView.kt`.
  Кто слушает — телефон или Bluetooth-гарнитура — выбирает владелец кружком
  в веере шестерёнки над «П» (`trigger/StackSettingsController.kt`,
  состояние — `settings.phoneMicOnlyFlow`); канал SCO поднимает и опускает
  `provider/MicRouting.kt`. Геометрия стопки — `core/StackGeometry.kt`,
  пружины и сжатие кнопок — `core/ChainPhysics.kt` + `trigger/BubbleMotion.kt`,
  серая «отмена» у любой записи — `trigger/CancelBubble.kt`.
- **Claude:** `provider/ClaudeProvider.kt` — только транспорт (HTTP, SSE-стрим,
  кэш промпта, ретраи, деньги через `Pricing.kt`, форма запроса по модели и
  усилию — `RequestPolicy.kt`) плюс Правка (чистка, обучение). Какая модель и
  с каким усилием на какой дороге — `data/ModelRoutes.kt` (каталог дорог и
  заводские) и `settings.modelChoice(ModelRoute.X)`; владелец меняет это в
  настройках, группа «Модели» (`ModelsSettings.kt`).
  Батчи (Message Batches API) — `provider/ClaudeBatches.kt`; ночной разбор
  Правки на них — `core/NightReview.kt` + `core/NightReviewPolicy.kt`,
  недельная правка промпта — `core/PromptTuner.kt` + `core/PromptTunePolicy.kt`
  (версии — `data/PromptVersions.kt`; слепой судья двух чисток —
  `core/ShadowPolicy.kt`; ночная тень второй модели снята 18.09), ручное
  сравнение трёх моделей (Сонет · Опус · Опус low, только кнопкой) —
  `core/ModelCompare.kt` + `core/ComparePolicy.kt`, эвал золотого
  набора — `core/EvalRunner.kt`; уборка на старте (прогоны тени, осиротевшие
  батчи у Anthropic) — `core/NightSweep.kt`; прогоны разбора, правки и
  сравнения — `data/NightReviewStore.kt`, экран — `ReviewsTab.kt` («Ещё →
  Разборы»);
  табло «что работает» и журнал автоматов `night.log` — `core/NightBoard.kt`,
  `app.nightLog` (автоматы пишут туда, не в общий лог службы).
  Запрос чистки одной формы для дня и батчей: `ClaudeProvider.cleanPromptParts`
  + `ClaudeBatches.cleanParams` + `RequestPolicy.maxTokens`.
  Разборы режимов — расширения того же класса рядом: `ClaudeZasechka.kt`,
  `ClaudeRaznoska.kt`, `ClaudeFood.kt`, `ClaudeBody.kt`, `ClaudeAnalysis.kt`.
  Контракты (`ClaudeProvider.XxxParse`) остаются вложенными в главный класс.
- **Промпты:** `core/Prompts.kt` — индекс и `assemble()`; тексты по режимам в
  `core/prompts/Prompts<Режим>.kt`. Владелец правит промпты на телефоне
  (`data/PromptStore.kt`), заводские тексты — запас.
- **Словарь, правила, обучение:** `data/DictionaryStore.kt`, `data/RulesStore.kt`,
  `data/LearnStore.kt`, `data/EditWatchStore.kt`, `core/ProofreadEngine.kt`,
  `core/EditDiff.kt` (правка одного слова руками → словарь без модели),
  `data/CorrectionsLog.kt` (журнал правок: надиктовано → модель → владелец,
  очередь для «Разобрать сейчас»). Захват правок — окно подписки на события
  текста после доставки (`armCapture` / `digestEdits` в службе), не
  постоянная подписка. Режим отладки — `ClaudeProvider.requestLogger` →
  `app.requestLog`.
- **Хранение и обвязка:** `data/StoreFiles.kt` (атомарная запись, `.prev`,
  `.corrupt`), `data/DiskWriter.kt`, `data/Backups.kt`, `data/Settings.kt`,
  `data/ModelRoutes.kt`, `data/EventLog.kt`, `data/Stats.kt`, `data/Updates.kt`,
  `ui/*`.
- **Служба доступности:** `trigger/PravkaAccessibilityService.kt` — хозяин
  микрофона, оверлейных окон, стопки кнопок и тиков. Режимные куски — расширения
  рядом: `trigger/ServiceZasechka.kt`, `ServiceRaznoska.kt`, `ServiceBody.kt`,
  `ServiceAnalysis.kt`. Сами кнопки — `*ButtonController.kt`.
- **Сборка приложения:** `PravkaApp.kt` (сервис-локатор: все сторы и движки),
  `MainActivity.kt` (вкладки), `SettingsTab.kt` (группы настроек),
  `ModelsSettings.kt` (группа «Модели»).

## Сборка и проверка

```bash
./gradlew compileDebugKotlin -PbuildNumber=999   # компиляция без сборки APK
./gradlew testDebugUnitTest -PbuildNumber=999    # JVM-тесты (app/src/test)
./gradlew assembleDebug                          # APK
```

В облачной сессии: SDK ставится в `/opt/android-sdk`, путь — в
`local.properties` (`sdk.dir=…`, файл не в git), Gradle есть в `/opt`. Перед
пушем — компиляция и тесты обязательны; новый случай разбора — сначала тест.

CI (`.github/workflows/build-apk.yml`) собирает APK на каждый пуш в любую ветку,
а в `apk-builds` публикует **только из ветки `pravka`** — единственной линии
Правки; телефон обновляется из неё (`Updates.LINE`). Рядом в `apk-builds`
лежат файлы Слушалки из её ветки `slushalka` — публикация их не трогает.

**Пушить сборки только в `pravka`** (владелец, 07.09.2026: «пушить сборки
только в pravka!»). Рабочая ветка сессии — черновик, который до телефона не
доезжает: сборка из неё остаётся артефактом workflow. Закончил работу —
компиляция, тесты, fast-forward `pravka` на свой коммит и пуш `pravka`; PR не
открывать. Если `pravka` ушла вперёд — сначала rebase своей работы на неё.
Новая работа — своей веткой от `pravka`, потом fast-forward `pravka` и удалить
рабочую ветку. PR не открывать без явной просьбы. Коммиты: тема по-русски,
дальше причины, как в истории.

## Железные правила (выжимка `docs/agreements.md`)

1. **Лента и дневник еды — незаменимые данные.** Пустой список поверх файла не
   записывается; миграции пишут только после чтения; сырая надиктовка не
   удаляется никогда. Кэш спорта и плана — расходный, но пустой ответ API в
   него не пишется.
2. **Складывание Fold — больная тема.** Ничего тяжёлого на главном потоке
   службы; окна не прятать через `GONE`, а снимать из WindowManager; за чужими
   окнами не подглядывать; на оконные события не подписываться.
3. **Внизу ровно шесть кнопок (Правка · Засечка · Дело · Спорт · Еда · Ещё), плавающих три: П · З · Д** (зелёная «Е» с 19.09.2026 выключена с завода, тумблер Еды возвращает её четвёртой). Связка и кольцо
   говорят с кнопками через `trigger/RingButton.kt`; порядок — `chain()` в
   службе; новая функция на стекле — новый `RingButton` в списке, не пятая
   переписанная копия контроллера. Серая шестерёнка (0,72 кнопки) — не
   кнопка режима: тап раскрывает веер быстрых настроек (модель чистки ·
   микрофон · обновления · спрятать всё), двойной тап — всё в точку с «П»;
   в стопке она над «П», на диске в центре. В меню долгого нажатия каждой
   кнопки есть «Настройки». Плашки микрофона между «П» и «З» и трёх точек
   над «П» больше нет (18.09.2026). С 19.09.2026 кнопки по умолчанию стоят
   **диском** вокруг шестерёнки (`trigger/DiskController.kt`,
   `core/DiskGeometry.kt`): «П» сверху, «З» снизу, крутится за любую кнопку,
   переезжает за стекло (или за шестерёнку по долгому нажатию), двумя
   пальцами — где бы ни взяли (щипок собирается в `DiskController.finger`
   со всех окон диска), у края виден до середины шестерёнки, двойной тап по
   свободному стеклу — веер, долгое нажатие на стекло — выдвинуть целиком и
   обратно, по простою убирается к ближайшему краю (тумблер «Автоматически
   убирать диск к краю»), под стеклом мягкая тень; выбор
   «Круг · Стопка» в Общих. Стекло с завода **светлое** (бумага) — тумблер
   «Стекло диска: Светлее · Темнее» там же, числа обеих шкурок и плотности
   слоёв — `core/DiskLook.kt` под тестами; кнопки, шестерёнка и кружки веера
   выпуклые — `trigger/BubbleSkin.kt`, наследник `GradientDrawable` на том же
   поле контроллеров. Новая
   вкладка — в `SERVICE_TABS` под «Ещё». Настройки — в одной вкладке по группам
   режимов, composable группы живёт в файле своего режима; шестерёнка в шапке
   вкладки открывает СВОЮ группу отдельным экраном (`ModeSettingsScreen`).
   **У каждой вкладки одна шапка** (`ui/Frame.kt`: `TabHeader`): пиктограмма,
   название с полоской, справа статистика · «$» · шестерёнка; пояснений под
   названием нет, содержимое — в плашках (`PaperCard`) с заголовками разделов
   и едва заметным узором знаков режима на плашке (`glyphPattern`); фон под
   плашками тёмный и чистый, лента Засечки — без плашки.
   Служебные экраны, стоимость и настройки режима открываются ПОВЕРХ вкладки
   (`Page` в `MainActivity`), «‹» и системный «назад» возвращают на неё.
4. **Еда ленту не отращивает** — только `ZasechkaStore.annotate`.
5. **Наружу пишем осторожно.** В Notion — только «Дневник» (свои колонки) и базы
   «Правка: разборы» по схеме `core/NotionLifeSchema.kt` (структура живёт в
   коде, приложение достраивает её само); в intervals не PUT-ить, не прочитав;
   наш блок в описании — между маркерами `[Правка]…[/Правка]`, идемпотентно.
   Параллельного трека в ленте нет: телефон считается по дням.
6. **Ошибку не затирать общей фразой**, HTTP-причина доходит до владельца целой.
   Молчаливая механика читается как поломка: отложенная дорога наружу называет
   состояние словами и даёт кнопку подтолкнуть.
7. **Модель и усилие — настройка владельца, не константа.** Каждый вызов
   Claude читает `settings.modelChoice(ModelRoute.X)`; дороги и заводские —
   `data/ModelRoutes.kt`. Заводские: разборы Засечки, Тела и Еды — Опус со
   стабильным префиксом под часовым кэшем (словарь `{DICT}` — в переменном
   хвосте), правка текста — Опус (с 18.09.2026, по тени 17:2 против
   Сонета), подсказки тренера — Сонет, сверка паттернов —
   Fable 5.1. `thinking: disabled` — только Сонету и только до high
   (`RequestPolicy`): Опусу с xhigh/max и Fable явное «disabled» — это 400.
8. **Подпись — только `keystore/pravka.jks`.** Прокси на VPS не делаем. Своей
   камеры не открываем (системный интент и сканер Play Services).
9. **intervals.icu:** поля `fatTotal` и `icu_rpe`; `optString` у JSON null
   отдаёт строку «null» — читать через `IcuSportSync.text(o, key)`.
10. **Строка плана — один парсер** `core/PlanLine.kt` (вкладка, отчёт зарядки,
    досыл в intervals). «Турник» — не зарядка; зарядка узнаётся по тегу или слову.
11. **Спецификация живёт в `docs/`.** Изменил поведение — поправь документ
    режима; новая договорённость — в `docs/agreements.md`; закрыл этап —
    `docs/status.md`. README — только карта.
12. **Сборки — только в `pravka`.** Телефон обновляется из одной ветки; работа,
    оставшаяся в своей ветке, для владельца не существует. Финальный пуш —
    fast-forward `pravka`.
