# Сборка, доставка и ветки

> Часть спецификации Правки. Была разделом README; правится вместе с кодом режима. Карта репозитория — `CLAUDE.md`, короткий обзор — `README.md`.

## Сборка и доставка

```powershell
.\gradlew assembleDebug    # просто собрать APK
.\gradlew installDebug     # собрать и поставить по adb
.\gradlew deliverApk       # собрать и отправить APK в Telegram
.\gradlew deliver          # собрать + adb-установка + Telegram
```

APK: `app/build/outputs/apk/debug/app-debug.apk`.

**Канал 0 — GitHub Actions (основной при облачной разработке).** Каждый пуш в
любую ветку собирает подписанный debug APK (артефакт workflow); в ветку
`apk-builds` он публикуется **только из линии `pravka`** (`pravka-debug.apk` +
`build-info.txt`). Рядом лежат файлы Слушалки из её ветки `slushalka`
(`slushalka.apk`, `slushalka-build-info.txt`): публикация забирает ветку,
меняет только свои файлы и пушит один осиротевший коммит с
`--force-with-lease`, повторяя попытку, если вторая линия успела раньше — так
ушла гонка «cannot lock ref» и подмена сборок. Для CI `versionCode = номер
запуска workflow` (общий на репозиторий), поэтому каждая следующая сборка
ставится поверх предыдущей. В `build-info.txt` едут `versionCode`,
`versionName`/`pravka`, `apk`, `commit`, `branch`, `builtAt` — последние два
нужны самообновлению (см. ниже).

**Канал 0б — приложение обновляет себя само.** Раз в сутки Правка читает
`build-info.txt` из `apk-builds` (репозиторий публичный, `raw.github…` отдаёт
файл без токена — нового секрета в приложении не завелось). Сделано по образцу
Слушалки (`slushalka/data/Updater.kt` в её ветке), плюс уведомление, потому что
владелец просил «чтобы говорила, если видит что-то новое».

- по Wi-Fi APK скачивается сам, потом уведомление «Обновление 2.0.NNN готово»
  → тап → системный установщик;
- по мобильной сети сначала уведомление «Есть сборка 2.0.NNN» → тап качает и
  ставит (тумблер «качать и по мобильной сети» снимает эту осторожность);
- **ветка сверяется.** Номер в `apk-builds` — номер запуска workflow, общий
  на репозиторий: сборка Слушалки всегда «новее» по числу и при этом не
  содержит твоей работы. Поэтому обновляемся только на свою линию —
  константу `Updates.LINE` = `pravka` против `branch=` в build-info. Чужую
  Правка покажет в настройках и не предложит. Линия — константа, а не
  `BUILD_BRANCH`: имя ветки сборки менялось при каждом переезде, и обновления
  молча прекращались. Поле «Обновляться из ветки» (пусто = `pravka`) осталось
  на случай переезда линии;
- имя файла берётся из build-info (`apk=`), а не угадывается;
- скачанный APK проверяется до установки: это должен быть `ru.zf.pravka` с тем
  самым `versionCode` — пока качали, в ветку мог приехать следующий билд.
  Если приехал именно следующий из нашей же линии (свежий build-info это
  подтверждает), качалка берёт его, а не выбрасывает файл с ошибкой: так
  случилось 02.09, когда пуш файла документации пересобрал ветку ровно в
  минуту, пока владелец качал предыдущую сборку («скачался не тот APK»).
  Чтобы такое случалось реже, CI не собирает APK на правки `README.md` и
  `docs/**`, а сам APK качается с тем же `?t=`, что и build-info, — иначе
  Fastly пять минут отдаёт прошлый файл к свежему описанию;
- в кэше лежит только свежий APK, после обновления он удаляется.

Проверку двигает пятиминутный тик службы и открытие приложения. Руками:
**Настройки → карточка «Обновления»** (рядом со службой, вне групп). Первая
установка попросит разрешить «ставить неизвестные приложения» — Андроид
спрашивает это один раз.

**Канал 1 — adb по Wi-Fi.**

```powershell
.\scripts\reconnect.ps1 -Pair 192.168.x.x:PORT -Code 123456
.\scripts\reconnect.ps1 192.168.x.x:PORT
.\scripts\reconnect.ps1            # после перезагрузки телефона
```

**Канал 2 — Telegram-бот.** `telegram.botToken` и `telegram.chatId` в
`local.properties`, дальше `.\gradlew deliver`. Без токена таска просто пишет
«skipping Telegram delivery».

**Версии.** `version.properties` хранит счётчик `buildNumber`; каждый
`assemble*`/`install*`/`deliver*` увеличивает его. `versionCode = buildNumber`,
`versionName = 2.0.<buildNumber>`. Файл коммитится, чтобы номера не
повторялись между машинами.

### Подпись — важно

Единый keystore `keystore/pravka.jks` используется для **всех** сборок,
включая debug. Никогда не подписывать другим ключом: установка поверх
сломается, и вместе с приложением сотрутся словарь, лента и настройки.

- Пароль хранилища и ключа: `pravka-keystore-2026`
- Алиас: `pravka`
- SHA-256: `B9:E9:79:F0:2C:F2:9D:EB:35:3D:CF:2B:CE:99:C5:FC:64:E5:1A:33:27:24:CB:B6:5C:53:28:25:64:53:11:B5`

### Первая настройка на новой машине

1. JDK 17+ и Android SDK (проще через Android Studio).
2. `local.properties.example` → `local.properties`, поправить `sdk.dir`.
3. Всё: пароли keystore уже прописаны значениями по умолчанию.
