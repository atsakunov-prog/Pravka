# Дела на домашнем сервере: замена Todoist и Notion CRM

> Часть спецификации Правки. Карта сервера — `server/pravka_dela/CLAUDE.md`,
> контракт с телефоном — `server/contract/dela.json`. Режим «Д» на телефоне —
> `docs/dela.md` (на сервере с 03.10.2026; Todoist — запасная дорога).

## Зачем

Владелец, 03.10.2026: «я хочу целиком из Notion и Todoist уйти. Эти базы не
работают, а вот моя Правка работает: я трекаю еду, деньги, и оно работает.
Поэтому давай всё сделаем на своём».

Что показали данные в тот день:

- в Todoist 41 открытая задача, около 30 просрочены с 5–9 сентября; метки
  людей живут рядом с префиксом «Кто:» в названии;
- Notion CRM («Сделки», «Контакты», «Лог взаимодействий») не обновлялся с
  начала мая;
- разбор встреч за сентябрь вынул 321 задачу из 40 встреч, и они лежат без
  дела — поток из автоматики больше, чем весь Todoist;
- таймер Засечки из задачи за полтора месяца ни разу не запускали.

Отсюда главное: центр системы — ежедневный и еженедельный разбор («Утро»,
«Неделя»), а не ввод. Ввода у владельца и так в избытке.

## Устройство

```
Правка ─────────────► dela.<роутер>:8443 ─┐
веб (Наташа, Марианна) ─► dela.<домен> (VPS) ─┤        PostgreSQL pravka
                                             ├─► ZF-Dela :8102 ─► схемы crm, tasks (роль dela_app)
claude.ai ─► архив /mcp ─(тот же код store)─┘                    виды в life — для Claude
встречи, юзербот ─► API службы, свои токены
```

- **Одна служба ZF-Dela**: API, позже веб и бот. Виртуальная учётка
  `NT SERVICE\ZF-Dela`, restricted, `C:\Bot` закрыт; секреты —
  `C:\ProgramData\ZF-Dela\secrets\dela.env`, а не `server.env` архива.
- **Claude** работает с делами в коннекторе «Правка»: архив регистрирует
  инструменты `dela_*`, если в `server.env` есть `DELA_DB_URL`, и зовёт тот же
  `store` под ролью службы. Для счёта — виды `life.tasks`, `life.projects`,
  `life.deals`, `life.people`, `life.interactions`, `life.work_time`.
- **«Где мы»** (10.10.2026) — точки семьи для карты Правки едут через эту же
  службу (`where.py`, `sql/dela_0008.sql`, контракт `server/contract/dela-where.json`):
  только `/api/ops` и `/api/view`, видит только семья (`crm.users.family`,
  команда `family`). Спецификация — `docs/gde.md`.
- **Дайджест Telegram** (13.10.2026, «Правка 5.0») — сводку переписки служба
  дайджеста на компе кладёт сюда (`digest.put` тем же токеном, что разноску в
  «Новое»), телефон берёт последнюю полем `digest` синка, список — видом `digest`
  (`digest.py`, `sql/dela_0014.sql`, контракт `server/contract/dela-digest.json`).
  Видит только владелец; новых путей HTTP нет. Телефону — `docs/digest-phone.md`.
  **По карточкам CRM** (14.10.2026, `digest_crm.py`, `sql/dela_0018.sql`; владелец: «дайджесты Телеграма надо
  разносить по карточкам CRM, а также складывать на сервере, чтобы через коннектор их можно было читать»): та же
  `digest.put` раскладывает пункты «Ждут тебя» и «По работе» в хронологию рабочего человека, его клиента и сделки
  (`crm.interactions`, kind `telegram`, source `digest`) — без Claude, узнаванием `people.who` по id Telegram и
  названиям чатов (служба шлёт `sources` — чаты окна). Семья (флаг `family`, Свод `people.family`, пока его нет —
  однофамильцы владельца) и личные чаты — мимо, новых людей не заводит. Запись `private`: команда её не видит ни в
  открытом ей клиенте, ни в журнале (у приватной записи его нет). Сводки — все, с 04.10.2026 (догрузка
  `C:\Bot\Digest\backfill_dela.py` на компе): вид `digest` ищет (`q`), берёт даты (`since`, `until`) и карточку
  (`person_id`, `project_id`), коннектор — инструменты `digests` и `digest`, веб — `#/digest`.
- **Код** — здесь, рядом с архивом: база общая, порядок `migrate` общий
  (архив после своего `DROP SCHEMA life` возвращает виды Дел), контракт
  с телефоном проверяют обе стороны.

## Решения

Принципы владельца — в `server/pravka_dela/CLAUDE.md` («Железные правила»).
Что решено по ходу и почему:

1. **«Новое» — не статус задачи, а таблица предложений.** Туда же ложатся
   «предложить закрыть» (увидели «отправил») и «предложить Марианне» (дело на
   неё — только с её согласия). Отклонённое с причиной и поправленное — материал
   для промптов. Неразобранное гаснет через 7 дней.
2. **Предложения пачкой.** Встреча — одна карточка: «мои обещания / всё / по
   одному». «Идеи» задачами не становятся.
3. **Проект = клиент, сделка — внутри.** В Todoist проект — клиент («Стеллар
   Групп»), в Notion у клиента несколько сделок («Стеллар: фонды», «buy-side
   M&A»…). Дело может ссылаться на сделку.
4. **Связь с лентой делает телефон.** `life` — виды поверх журнала телефона:
   колонку в `life.entries` не добавить на сервере. Запись Засечки, начатая из
   дела, хранит `task` и `project`; старые записи сопоставляются по алиасам
   справочника в виде `life.work_time`. Сырой текст клиента не переписывается.
   С 03.10.2026 поля записи видны в `life.entries` (`task_id`, `project_id`), а
   `life.work_time` берёт проект по порядку: проект записи → проект её дела →
   клиент текстом по алиасам (`task_num` — номер дела).
5. **Синк — «всё после seq» с перекрытием.** Номер изменения берётся до
   фиксации транзакции; окно в 200 номеров ловит опоздавших. Новый или снятый
   доступ — ответ целиком.
6. **Офлайн — очередь операций с op_id.** Повтор безвреден; спор правок — по
   полям, побеждает последнее, клиент узнаёт о споре, прежнее — в журнале.
7. **Вход людей в веб — через бота.** Виджет Telegram грузится с
   `oauth.telegram.org`, а он в России без VPN не открывается. «Войти» на
   сайте — подтверждение в боте — по желанию passkey. Паролей нет.
8. **Перенос — сухим прогоном.** Отчёт спорного владельцу, потом запись. id
   строк выводятся из id источника: повтор переноса обновляет те же строки.
   Решения владельца (кто есть кто) — в его локальном файле: репозиторий
   публичный.
9. **До переезда телефона Todoist — только вход.** Пока Правка шлёт голос в
   Todoist, служба забирает оттуда **новые** задачи в одну сторону и ничего в
   Todoist не пишет. Правка и закрытие — уже в Делах.
10. **Разбор текста Claude в вебе — сразу в дела, не в «Новое».** Рядом с «+»
    в каждом поле нового дела — звёздочка Claude (или Ctrl+Enter): текст
    уходит на `POST /api/parse`, Claude Opus 5.5 режет его тем же промптом,
    что Разноска телефона (с 06.10.2026 — один файл
    `server/contract/prompts/raznoska.txt`, см. решение 12), со
    справочником только видимых этому человеку проектов, людей и меток.
    Кнопку жмёт сам человек, поэтому дела заводятся сразу; «Новое» — только
    для автоматики. Отмена — одной кнопкой в итоге разбора (дела уходят в
    отменённые, журнал помнит). Факты, которые не дела, — заметки в
    хронологию. Разбор — заданием (`GET /api/parse/<номер>`): ответ модели
    бывает дольше минуты, а роутер и nginx долгие запросы рвут. Ключ —
    `ANTHROPIC_API_KEY` в `dela.env` (установщик берёт ключ встреч), к API —
    через xray бота `127.0.0.1:11809`.
11. **Подсказки при вводе.** `+` — проекты, `@` — люди, `*` — метки, `!` —
    команды: выпадающий список, стрелки, Enter или Tab, Esc. Имя со
    пробелом вставляется в кавычках, тёзке — полное имя: разбор строки
    потом узнаёт ровно того, кого выбрали.
12. **Напоминания — в Telegram ботом, правила разбора — одним файлом** (06.10.2026,
    задание — `docs/dela-server-remind.md`, контракт — `server/contract/dela-remind.json`).
    Владелец: «напоминания через мой Ковчег-бот… „напомни в 11:00“ или „когда приеду
    домой“». Поля дела `remind_at`, `remind_place`, `reminded_at`; по месту момент ставит
    телефон (он один видит приезд), шлёт сервер через бота. Сервер, который их знает,
    отдаёт `features: ["remind"]` — без флага телефон полей не шлёт. Правила разбора
    наговора — `server/contract/prompts/raznoska.txt` для телефона и `parse.py` сразу:
    две копии с припиской «правь обе» уже начали расходиться.
    Сервер сделан 06.10.2026: шлёт служба встреч ботом Ковчега (у неё getUpdates этого бота
    и его кнопки), раз в 30 с забирая у Дел `GET /api/reminders/due` токеном `kovcheg`;
    кнопки «Сделано · Через час · Завтра 9:00» — `POST /api/reminders/act` от имени нажавшего
    (Дела узнают его по `crm.users.telegram_id`). Марианне — только напоминания, которые она
    поставила себе сама (правило 6).

13. **Одна правда — на сервере: Свод и одна карточка человека** (06.10.2026, контракт —
    `server/contract/svod.json`, задание телефону — `docs/svod-phone.md`). Владелец: «правда
    должна быть на сервере, телефон больше читает… если я в расшифровке встречи человека
    поменял, это должен понимать и телефон, и CRM, и сервер». Свод (`crm.svod`) — промпты,
    словарь, правила, справочники владельца: ключ, текст или JSON, версия, автор; телефону —
    обычным синком, службам компа — видом `svod`, сессиям — `python -m pravka_dela svod`.
    Последний пишущий побеждает, автоматы шлют `base_rev`. Человек — строка `crm.people` на
    всю систему: вид `who` (номер, Telegram, почта, имя с уменьшительными, падежами и
    компанией), `person.add` дописывает имена и номера, `person.merge` сливает дубль (строка
    остаётся с `merged_into`; с 15.10.2026, аудит №23, — только владелец и функцией базы
    `crm.person_merge` мимо прав сливающего: дела, сделки с командой, хронология, участники встреч,
    ждущие вопросы, семья в Своде; номер, Telegram и почта дубля `who` отвечает живой). Встречи связывают спикеров с людьми и дописывают карточкам
    имена, которые дал владелец; «Деньги» кладут в Свод правила партнёрства и итоги узким
    токеном (`api.SCOPED`: только `svod.set` и вид `svod` с ключами `money.*`).
    С 15.10.2026 (аудит, №4) узкому токену службы положены только пути `api.SCOPED_PATHS` —
    `GET /api/me` (вид Ковчега, без данных владельца), `GET /api/view/<имя>` и `POST /api/ops`,
    дальше прежние проверки `SCOPED`; всё остальное — 403 одной обёрткой маршрутов. Своё имя
    сильнее чужого другого имени (аудит, №1, `dela_0020`): `crm.match_name` и `who` — сначала
    имя или короткое имя карточки, потом её другие имена; `person.add` чужое имя другой живой
    карточки не дописывает (`skipped`); двусмысленное имя в «Новом» — вопрос «Кто это — X или
    Y?» кнопками, причина ожидания — `payload.held` (правила 14 и 15 в
    `server/pravka_dela/CLAUDE.md`, телефону — `docs/dela-phone-21.md`).

14. **Наговорки в «Новом», карточки с Claude, «Сейчас» до пяти** (06.10.2026, правило 15 в
    `server/pravka_dela/CLAUDE.md`). Владелец: «утро непонятно, что это… входящие — чем они
    отличаются от нового… новое как последние 10 наговорок, и там будет указано, какие дела куда
    попали… в любой карточке клиента или человека сверху текстбокс Клода… и это должен делать
    Опус… если нажимаю на проект, он должен быть не сайдбаром, а таким же, как клиент». Наговорка
    — строка `tasks.dictations` (текст дословно), дела ссылаются на неё своим `source_ref`; разбор
    на сервере пишет её сам, телефон — операцией `dictation.add` (флаг `features: ["dictations"]`,
    задание — `docs/dela-phone-3.md`). Правка словами в карточке — Opus 5.5 и массив `card`
    (хронология, люди, сделки); проба на API показала предел грамматики ответа — поэтому `card`
    один, без перечислений, а у `create` — только нужные поля.

15. **Круг жизни: направления и «Зачем»** (12.10.2026, правило 19 в `server/pravka_dela/CLAUDE.md`; дерево целей
    7.2 — 13.10.2026, `dela_0013`, телефон — `docs/dela-phone-14.md`).
    Дерево 7.2, решения: цель — по-прежнему дело (как три цели лесенкой в 7.1), но с явной пометкой `goal` в строке
    Круга: без пометки пустая цель переставала быть целью, а восемьдесят с лишним узлов брифа легли бы в
    «Запустить». Узел — без проекта (видит только хозяин; `crm.sees_task`), отдельной сущности «цель» нет — цепочка
    «Зачем», журнал, синк и карточка те же. Главное направление — у корня цепочки, свои — метки: одно правило в
    `tasks.krug_dirs`, `dirsOf` веба и телефона. Засев дерева — один раз на версию файла владельца (`crm.state`
    `krug_seed`): установщик зовёт `krug-seed` каждый раз, и повтор не должен возвращать перенесённое.
    Владелец принёс бриф («каждое моё дело должно преследовать какое-то направление… дела, которые двигают
    жизнь, проигрывают любому входящему запросу») и упростил его тем же вечером: направление вместо «часа»,
    без линий, у дела одно или несколько направлений, вместо DoD — «Зачем» и многоуровневые планы, дерево дел от
    направлений. Решения:
    - **Отдельная таблица `tasks.krug`, а не колонки дела.** Круг личный: колонка уехала бы Наташе и Марианне
      синком (`v_tasks` собран через `t.*`), журналом карточки и выгрузками; своя таблица под политикой «только
      хозяину» прячет всё сама. Цена — синк дел смотрит и на `krug_seq`.
    - **Цель — обычное дело с шагами**, а не новая сущность «проект с DoD»: название цели и есть результат,
      закрыть цель — результат есть (в движении — три события). У сделок «зачем» — сама сделка: лид — договор,
      мандат и работа — закрытие; проекты остаются про то, кто видит («Семья» — что видит Марианна).
    - **Справочник — Свод, не код и не таблица.** Тексты направлений личные (имена, клиенты, терапия),
      репозиторий публичный; Свод синкается на телефон, попадает в копии базы, у каждой правки версия.
    - **Один разборщик на сервере, а не шесть входов.** Дела заводят телефон, встречи, дайджест, Telegram,
      строка Claude и коннектор; учить каждый направлению — размножить промпт (LOGIC §11 и так жалуется).
      Разборщик пачкой проходит по делам без направления по расписанию владельца («раз в полчаса… ночью раз в
      8 часов… в выходные раз в час»): нет таких дел — ни одного запроса. Уверен — ставит, не уверен —
      «Подскажи». Учится на правках владельца в Круге (журнал); механизма «учиться на причинах отклонения»,
      на который ссылался бриф, в Делах не было.
    - **Без кэша.** Запросы реже раза в полчаса: пятиминутный кэш не доживёт, часовой дороже входа, пока за час
      нет двух запросов.

16. **Встречи — в базе целиком** (12.10.2026, правило 20 в `server/pravka_dela/CLAUDE.md`; задание серверу 4 — `docs/dela-server-meetings.md`). До этого
    служба встреч отдавала Делам только сводку в хронологию; теперь — встречу с расшифровкой
    (`meeting.upsert`), а сервер сам даёт ей единое название «Клиент: тема», участников и «рабочая / личная»
    (`meetings_auto.py`). Веб — CRM → «Встречи»; Claude — `meetings`, `meeting`, `meeting_change`. Первый шаг
    к «офис-менеджеру ЗФ»: ему нужны встречи в базе и граница личного. Архив (198) служба догнала 12.10; дальше
    его не догоняем (владелец 13.10: «старые уже ушли в прошлое») — своей расшифровкой не переделываем, вопросы
    разбора — только о свежих встречах (`dela_0011` погасила 36 вопросов архива).
    **Клиент переименован — встречи следом** (13.10.2026, `dela_0012`; владелец: «переименую клиента — чтобы и в
    истории встреч переименовалось»): правило базы на `crm.projects` — встречи проекта берут новое имя, старое
    ложится в другие имена клиента, встречи с подписью нового или переименованного клиента пристёгиваются к нему.
    Клиент без справочника (подпись «Вера (клуб)») — `meeting.set everywhere`. В вебе — «Переименовать» в карточке
    клиента и «поменять у всех?» в карточке встречи; Claude — `client_rename`.
    **Одна правда о встрече — её карточка** (15.10.2026, аудит №6, №43, №3, `dela_0021`, фича `meeting_touch`):
    запись встречи в хронологии клиента ведёт сервер (`crm.meeting_touch`) — клиент, сделка, люди и «<название
    Дел>: <итог>» с карточки, одна живая на встречу, личная и без клиента — убрана; убрал или поправил её сам
    владелец — замок `touch`. Пачки «Нового» встречи — названием Дел. **Названный во встрече — в CRM** (аудит
    №25/№60, фича `people_link`): служба встреч предлагает неузнанного спикера, сервер сам заводит, спрашивает или

18. **«Сейчас» и «Сегодня» — врозь** (13.10.2026, этап 4 «Правки 5.0», правило 17 в `server/pravka_dela/CLAUDE.md`;
    телефон — `docs/dela-phone-19.md`). Владелец: «В делах давай разделим: Сейчас (то, что отметил) и Сегодня (с
    датой сегодня)»; порядок на экране — Сейчас → Новое → Сегодня; просроченное — во «Все дела». С 10.10 «Сегодня»
    было котлом: срок сегодня или прошёл, «Сейчас», «отбить» без срока, «мониторить» с напоминанием, — и то, что
    владелец сам взял на день, в нём тонуло. Решения:
    - **Три условия на сервере, а не в каждом клиенте** — `store.NOW_IF` (отметка `focus_on` на сегодня, предел пять —
      `_now_guard`), `TODAY_IF` (срок ровно сегодня), `LATE_IF` (срок прошёл); виды `now`, `today`, `all` (у `today` —
      числа `now_count` и `overdue_count`, у `all` — список `overdue` сверху). Веб и телефон считают то же по синку (`isNow`,
      `inToday`, `isLate`), коннектор Claude — теми же видами `dela_view`.
    - **«Отбить» без срока и «мониторить» с напоминанием в «Сегодня» сами не встают.** «С датой сегодня» — значит
      срок; у «отбить» нет даты, напоминание человеку — не срок. Они во «Всех делах»; взять на день — молнией
      («Сейчас») или сроком сегодня («Когда», «Перенести»); солнца «на сегодня» нет с 14.10.2026. С 15.10.2026
      (аудит №5) их видно числом в шапке «Сейчас»: «ждут от тебя без срока: N · жду больше недели: M» — ссылками на
      фильтры по людям; у вида `today` — `owed_nodue_count` и `waiting_stale_count` (`store.OWED_NODUE_IF`,
      `WAITING_STALE_IF`: ждёт дольше 7 дней, напоминание не назначено или прошло — то же, что `week.waiting_stale`).
    - **`later` («Дальше») — теперь старое имя «Всех дел»**, а не отдельный список: коннектор мог его запомнить.
    - **«Моё» Круга — подсказка под «Сегодня»**, не его часть: в нём нет того, что и так на виду (срок сегодня,
      «Сейчас»), и отбор трёх — после этого, а не до.
    - **На главной веба дело — один раз:** «Сейчас» со сроком сегодня в блоке «Сегодня» не повторяется; в виде
      `today` и на странице «Сегодня» оно есть (там его видно жирным и строкой «в «Сейчас»» у коннектора).

19. **Шаги и контакт сделки — одним правилом, упоминание — не контакт** (15.10.2026, аудит №2, №3, №7, №28,
    `dela_0022`, фича `deal_steps`; правила 12 и 21 в `server/pravka_dela/CLAUDE.md`; телефон — `docs/dela-phone-21.md`).
    С 05.10 автоматика не ставила сделку ни одному делу — 8 из 23 живых сделок горели «застывшими» при живых делах
    клиента; карточка сделки не видела своих встреч (запись встречи ложилась без сделки); «последний контакт» сделки веб
    считал с записями клиента, коннектор — без; упоминание клиента в сводке Telegram было «контактом». Решения:
    - **Пока сделка у клиента одна живая — его дела и записи без сделки тоже её** (`crm.only_deal`): шаги (`open_tasks`,
      `next_task.via_client` — «дело клиента»), хронология (`crm.deal_records`: не из Notion, не раньше её заведения),
      контакт (`crm.deal_last_touch`, та же функция у коннектора). Данные не переписываются — это правило вида: вторая
      живая сделка, и дела клиента снова ничьи. Почему не «записать сделку всем делам клиента»: у клиента появится вторая
      сделка — и половина его дел окажется не там.
    - **Сделку называют те, кто знает**: сверка встреч и разноска дайджеста — точным именем (`payload.deal_name`,
      `store._names`); у клиента с одной живой сделкой дело автоматики получает её само; дело, сказанное владельцем, —
      никогда (молча к сделке не пристёгиваем). Запись хронологии без ключа `deal_id` — «сделка касания»
      (`crm.touch_deal`; ключ `null` — слово человека); запись встречи — сделка карточки, пусто — сделка касания.
    - **Упоминание — флагом, а не удалением**: в хронологии видно, что о клиенте говорили, но «последний контакт»
      клиента, сделки, «Связей» и `life.people` его не считает. Контакт — «Ждут тебя» и темы, чей чат (группа клиента,
      личный чат его человека) был в окне. Старым записям — разово `digest-relink`.
    - **Встречи — в карточке сделки и клиента** (`meetings`, только владельцу), все — страницей «Встречи» с `deal_id`.
      В вебе — блок «Встречи» (строки как на странице «Встречи») и «все встречи проекта →» (`#/meetings/deal=<id>`,
      у клиента — `#/meetings/client=<id>`).
20. **Слияние людей, сигналы на виду** (15.10.2026, аудит №23, №5, №29, №19, `dela_0023`; правила 5, 15, 17, 25 в
    `server/pravka_dela/CLAUDE.md`; телефон — `docs/dela-phone-21.md`).
    - **Склеивает людей только владелец — и целиком**: `crm.person_merge` (SECURITY DEFINER) переносит все ссылки мимо
      прав сливающего — прежде RLS молча оставляла на дубле невидимое сливающему, а участники встреч, команда сделки,
      ждущие вопросы и семья в Своде не переезжали вовсе. Уже слитый — отказ. Ключи дубля (номер, Telegram, почта) `who`

      получит то же.
    - **«Ждут без срока» и «жду больше недели» — числами в шапке «Сейчас»**, а не сроками в данных: выдуманный срок
      нарушил бы правило разбора и раздул «Просрочено».
    - **Счётчик откатов автоматики** — `week.automation`: что сделано само за неделю и сколько вернули, ответы на
      вопросы. Без журнала — по «Новому» и текущему состоянию дел: число нужно, а не история.
    - **Цели дерева автоматика не закрывает и не правит** — «закрыть» и «уточнить» цели ждут владельца.
21. **Захват — «сказал → легло → вернётся»** (15.10.2026, шаг 0 петли этапа 4, `dela_0032`; правило 29 в
    `server/pravka_dela/CLAUDE.md`; контракт — `server/contract/dela-capture.json`, телефону — `docs/dela-phone-25.md`).
    - **Одна дверь — сервер.** «сказать», «Д», «З» и строка веба шлют фразу операцией `capture.say`, а не каждый своей
      развилкой: до этого одна фраза расходилась («идея: …» — мысль в ленте у «сказать», дело у «Д»). Операция, а не
      новый путь: закрытый список посредника на Aeza уже пропускает `api/ops` и `api/view/<имя>`, и даром — `op_id` и
      очередь без связи.
    - **Сначала правило, $0.** Одна мысль известной формы («напомни в 12 …», «когда приеду домой …», «идея: …», «Иван
      сказал …», «позвонил Ольге», «… на неделе», «купить магний») — за миллисекунды и без ключа Claude; остальное — модель
      на сервере (тот же Свод `prompt.raznoska` с блоком КОРЗИНЫ). Шесть живых фраз Саши уходят правилом. Корзину выбирает
      код по полям, правило сильнее модели: «напомни в 12» модель не уведёт в кучу.
    - **Напоминание — вид дела, не новая таблица** (`kind remind`): синк, очередь, журнал, RLS, бот и приезд телефона
      работают как есть; в списках дел его нет. Главный канал — уведомление телефона, бот — запасной через 10 минут
      (`remind.PHONE_GRACE_MIN`; было 3 — отметка показа без сети не успевала, и бот присылал то же второй раз). На
      «Сегодня» — сегодняшние и вчерашние; старше — во «Все дела → Напоминания: прошли — не отмечено»
      (`REMIND_STALE_IF`), иначе смахнутое уведомление висело бы на «Сегодня» бессрочно.
    - **«Потом» — день возврата, а не выдуманный срок** (`back_on`): «Вернулось» на «Сейчас» в свой день, не тронул —
      понедельник; просроченным оно не становится.
    - **Идеи — своя маленькая сущность** (`crm.ideas`, ответ 5а), только хозяину; «сделано» — `task.did` (spec-5 §2).
    - **`/api/parse` остаётся прежним путём** (без корзин) для старых клиентов; строка веба раскладывает новое через захват.
    - **Сквозной тест с настоящей моделью** (15.10.2026, тестовая копия Дел, Opus 5.5 high, $0,66 при потолке $2): шесть
      живых фраз и восемь вариантов тех же форм — правилом за 0,1–0,35 с; десять свободных фраз — моделью за 5–13 с
      (в среднем 7,6), голова под кэшем (~12 тыс. токенов) читается со второй фразы, ~$0,01–0,02 за фразу. Шесть живых
      фраз моделью мимо правила легли в те же корзины. Пойманное и поправленное: «в 12 … не забыть» модель давала сроком и
      напоминанием в один миг — это напоминание, а не дело в куче; «отправил договор Ивану» не находило Ивана после
      предмета и не гасило «Отправить договор Ивану»; «Ольга говорит, подпишут в среду, надо подготовить счёт» правило
      клало заметкой целиком — факт и дело теперь у модели; заметка модели «Иван сказал, что …» — сам факт, как у
      правила; «напомни Наташе про сверку» — напомнить ей самому, не «жду» от неё; «сказал Ивану, что пришлём …» —
      одно обещание без лишнего «сделано»; строки «жду» и «отбить» со сроком говорят, чьё дело, и не повторяют
      человека; «Ромашка: идея — …» — правилом, а не моделью; фоновый цикл больше не берёт наговорку строки веба,
      пока та сама ждёт модель (было два набора дел); кнопка под строкой работает с делом, каким оно стало после кнопок
      уведомления. Отчёт по живым фразам — «куда легло, что Саша увидел, когда вернётся» — у владельца на компе.
    - **Проверка 16.10.2026 — строки обещают только то, что правда случится.** Заметка — «· в карточке» (у встречи
      телефон показывает только идеи), идея ни к кому — «· в списке «Идеи»», вопрос о похожих — «· вопрос в «Подскажи»»
      (он встаёт туда сразу, вечернего захода до шага 2 нет), касание — «звонок у Ольги»; «Разложил N» называет, что
      именно («сделано: позвонил Ольге · на завтра: подготовить договор»), день недели — с датой («во вторник 20.10»),
      напоминание о «жду» — без двойного двоеточия. Правило молчит там, где раньше уверенно промахивалось: «когда буду
      свободен» — не место (место после «приеду/буду» — только «домой» или предлог и слово; незнакомое — как сказано, «к
      маме», «в Москве», и честное «телефон не знает»), «Иван хочет / обещал / просил …» — глагол и есть смысл, решает
      модель. Узнаёт больше: «не дай мне забыть …», «напомни про оплату аренды» (название «Про оплату аренды»), «идея для
      Ивана: …» (адрес снимается с текста). «Иван прислал модель» при одном «Иван: прислать сверку» сверку больше не
      закрывает: предмет сказан и не совпал — вопрос «Это закрывает…?», а обещание без своего предмета («Позвонить
      Ольге») закрывается и «позвонил Ольге по договору». **Тёзки** («Иван сказал…», «позвонил Ивану» при двух Иванах):
      запись без человека, под строкой одна кнопка «Какой Иван ▾» (не случайный Иван первым в пилюле) и тот же вопрос в
      «Подскажи» — `tasks.suggestions` вида `capture` (dela_0032), ответ — тот же `capture.move person`: заметка встаёт к
      человеку, сделанное закрывает его обещание и пишет касание. У напоминания первая кнопка — «Время ▾» (частая
      поправка), потом «Это дело». Сбой сети к Claude — повтор через 5, 15, 45 с, а не «не разложил» сразу; два разбора
      разом.
    - **Поезд 16.10.2026 — захват вместе с вложенностью, приватностью, защитой и отладкой.** Миграция — `dela_0032`
      (в ветке `dela_0024c`): `tasks.v_tasks` — от последней сборки (`dela_0030`: `pos`, `why_goal`) с колонками захвата,
      `crm.person_merge` — от `dela_0027` (и «Только тебе») плюс идеи. Напоминание — не дело внутри: не вкладывается и в
      него не кладут (отказ словами), подъём родителя, `steps_open` и «Внутри» — только по делам; «потом» не перебивает
      срок, унаследованный от родителя (`store._back_inside`). Слова вложенности («вынуть … из …», «вложи …», «для
      этого …», «к делу про …») правило не берёт — их разбирает Claude строки (`into`, `step`). Модель захвата — через
      защиту от петли (`guard.client`, задача `capture`); правило строки веба не тратит суточный предел не-владельцу и
      работает сверх него. Идеи — в «Где живёт приватное» правила 26 и под метлой. Снимок отладки несёт напоминания и
      «потом». Встречи: вход по теме (`focus.select`) — тоже без напоминаний.
