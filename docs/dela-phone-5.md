## 1. Что считать «сделанным само»

Было (`Dela.Suggestion.autoClosed`): `kind == "close" && status == "accepted" && payload.auto`.
Стало — по причине решения, а не по флагу: предложение с `payload.auto`, которое человек принял
руками (старая встреча), сюда попадать не должно.

```kotlin
val autoDone: Boolean
    get() = (kind == "close" || kind == "update") && status == "accepted" && reason in AUTO_REASONS
// AUTO_REASONS = setOf("закрыто само", "уточнено само") — store.AUTO_REASONS сервера
```

Поле `reason` у предложения в синке уже есть. Счётчик «Нового» (`DelaViews.counts`) и Засечка берут
`autoDone` вместо `autoClosed`.

## 2. Блок в «Новом»

Заголовок **«Сделано само»**, подпись «закрыл и уточнил по встречам и Telegram», «Понятно, все» —
как было. Строка:

- закрытие — «Закрыто: #N название», пачка и дата, основание (`quote`); «Вернуть» — `task.reopen`;
- уточнение — «Уточнено: #N название» (название уже новое), под ним что поменялось — из
  `result.was` (как было) и самого `result` (как стало): «название: «…» · срок 17.10 → 12.10 ·
  мяч: жду Ольга» (имя — `payload.person_name`); подробности `payload.note` отдельной строкой (как
  «+ подробности» у предложения), пачка и дата, основание. «Вернуть» — `task.set` с `set = result.was`.

У обоих «Вернуть» ещё убирает комментарий-основание, если сервер его записал: `result.comment_id` →
`{"op": "comment.delete", "id": "<comment_id>"}`; у старых закрытых его нет — тогда без этого шага. И
тот же `suggestion.seen`, после — тост «вернул в работу» или «вернул как было: <старое название>».
Пачкой, одной отправкой:

```json
[{"op": "task.set", "id": "<task_id>", "set": {"due_date": "2026-10-17", "title": "Альфа: КП на управленку"}},
 {"op": "comment.delete", "id": "<comment_id>"},
 {"op": "suggestion.seen", "ids": ["<suggestion_id>"]}]
```

«Вернуть» видно, когда есть что вернуть: у закрытия — дело ещё `done`, у уточнения — непустой
`result.was` или `comment_id`.
