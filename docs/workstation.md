# Правка на воркстанции (Windows 11)

Тот же режим «Правка», что на телефоне, только вход — не плавающая кнопка, а
горячая клавиша, и распознаёт не Google, а **твой локальный Whisper на GPU**.
Словарь, правила, промпты, расшифровки и статистика — общие: телефон и
компьютер сводятся через таблицу в твоём Google-аккаунте.

Документ отвечает на три вопроса: **что именно переносим**, **из чего это
собрано** и **как данные держатся едиными**.

---

## 1. Что переносим: функции Правки и их вид на Windows

| Функция на телефоне | Как это выглядит на воркстанции |
|---|---|
| Тап по «П» → диктовка → текст в поле под курсором | Горячая клавиша: **зажал** — говоришь, **отпустил** — текст встал в поле. Короткий тап — режим «говорю долго», второй тап останавливает |
| Голосовые команды («с новой строки», «новый абзац») | Тот же `core/VoiceCommands.kt`, применяются до вставки |
| Долгое нажатие → меню (Причесать, Короче, Длиннее, Отшлифовать, Отменить, Обучить, Сброс) | Вторая горячая клавиша открывает то же меню плашкой у курсора; каждый пункт — своя клавиша, если захочется |
| Оранжевые: Коротко, Ответить, Перевод | Там же, вторым рядом; ответ уходит в буфер |
| Выделение сужает действие | Выделение читается через `Ctrl+C` в буфер (см. §2.4); нет выделения — работаем с буфером |
| Стриминг ответа прямо в поле | Ответ течёт в плашку поверх окон, готовый текст вставляется одним куском |
| Словарь (HARD / HINT / PROTECT), Промпты, Обучение, Расшифровки, Статистика, Эвалы | Отдельное окно на Compose Desktop с теми же вкладками. На настоящей клавиатуре словарь наконец удобно править |
| Плитка в шторке, «Обработать текст» | Не нужны: их роль на компьютере играют горячие клавиши и трей |
| Засечка, Разноска, Дела | **Не переносим.** Ты просил только Правку; ядро общее, так что добавить потом — вопрос экрана, а не движка |

Дополнительно появляется то, чего на телефоне нет и не может быть:

- **Whisper large-v3 на GPU** вместо мобильных `small`/`base` — качество
  распознавания русского заметно выше, а латентность на короткой фразе ниже.
- **Подсказка распознавателю словарём**: HARD/HINT-слова, встречающиеся в
  твоём словаре, уезжают в Whisper как `initial_prompt`. Фамилии и термины
  начинают распознаваться правильно **до** правки, а не чиниться после.

## 2. Архитектура

### 2.1 Три модуля вместо одного

```
Pravka/
  core/      ← НОВЫЙ. Чистый Kotlin/JVM: вся логика Правки
  app/       ← телефон (Android): экраны, служба доступности, кнопки
  desktop/   ← НОВЫЙ. Windows: горячие клавиши, трей, плашка, окно вкладок
```

В `:core` уезжает ровно то, что не знает про Android:

- `core/*` — `ProofreadEngine`, `DictionaryApplier`, `Prompts` (все 544 строки
  промптов), `ResponseCleaner`, `VoiceCommands`, `UndoStack`, `EvalRunner`;
- `provider/ClaudeProvider`, `Pricing`, `DictMiner` — это уже чистый OkHttp;
- файловые сторы — `DictionaryStore`, `RulesStore`, `PromptStore`,
  `LearnStore`, `EditWatchStore`, `HistoryLog`, `TranscriptionLog`,
  `StoreFiles`, `DiskWriter`. Сейчас они берут `Context` ради одной строчки —
  `context.filesDir`. Меняем конструктор на `dir: File`, и они работают везде.

Абстрагируются три вещи, у которых на платформах разная природа:

| Что | Android | Windows |
|---|---|---|
| `Settings` (интерфейс) | DataStore | `settings.json` в `%APPDATA%\Pravka` |
| `Stats` (интерфейс) | DataStore | тот же `settings.json`-сосед `stats.json` |
| `TextTarget` (уже интерфейс) | `AccessibilityTarget` | `WindowsTarget` (§2.4) |

**Почему так, а не «переписать на Python».** Ценность Правки — не в записи
звука, а в промптах, словаре, правилах, чистке ответа и границах слов для
кириллицы. Всё это уже написано и обкатано. Общий `:core` означает, что
исправление в промпте одинаково доедет и до телефона, и до компьютера, и
разъехаться они не могут физически. Python-утилита была бы готова на день
раньше и разошлась бы с телефоном на первой же правке промпта.

### 2.2 Распознавание: сервер, а не запуск из командной строки

Сейчас у тебя `large-v3` запускается процессом на каждую задачу, и час встречи
разбирается 10–15 минут. Из этих минут заметная часть — **загрузка модели в
видеопамять при каждом запуске**. Для диктовки это смертельно: фраза на 10
секунд не может ждать 20 секунд прогрева.

Решение — держать модель загруженной:

- `scripts/whisper/server.py` — маленький сервис на `faster-whisper`
  (та же модель, движок CTranslate2 вместо референсного PyTorch: обычно
  в 3–5 раз быстрее и в 2 раза экономнее по видеопамяти). Модель грузится
  один раз при старте и живёт в GPU.
- API — **OpenAI-совместимое**: `POST /v1/audio/transcriptions`. Это стандарт,
  так что тем же сервером смогут пользоваться и другие твои инструменты, а
  Правка не привязывается к конкретной реализации: захочешь заменить движок —
  меняешь URL в настройках, приложение не трогаем.
- Автозапуск при входе в систему — `scripts/whisper/install-service.ps1`
  (задача в планировщике, окна нет).

Модели: для диктовки по умолчанию `large-v3-turbo` (короткая фраза
распознаётся за доли секунды), для часовых встреч — `large-v3` по параметру
`model` в запросе. Обе живут в одном сервере, вторая подгружается по первому
обращению.

Ожидаемая арифметика после перехода: час встречи — единицы минут вместо 10–15,
фраза диктовки на 15 секунд — меньше секунды.

### 2.3 Что происходит по нажатию клавиши

```
зажал клавишу
  → TargetDataLine пишет 16 кГц моно PCM16 (тот же WAV, что на телефоне)
  → отпустил
  → POST на localhost:8178/v1/audio/transcriptions (+initial_prompt из словаря)
  → VoiceCommands.apply()          // «с новой строки» → перевод строки
  → DictionaryApplier.prepare()    // HARD-замены + блок {DICT}
  → текст вставлен в поле под курсором
  → (если включено) CLEAN через Claude, результат течёт в плашку и заменяет вставленное
```

Каждая попытка — как на телефоне — ложится в `transcriptions.jsonl` с
метриками (движок, длина аудио, время, символы), а WAV остаётся на диске:
неудачную попытку можно переразобрать.

### 2.4 Как попасть текстом в чужое окно

У Windows нет службы доступности в андроидном смысле, поэтому:

- **Вставка**: текст кладётся в буфер, шлётся `Ctrl+V` (`java.awt.Robot`),
  через 300 мс прежнее содержимое буфера возвращается на место. Печатать
  посимвольно нельзя — на кириллице и на раскладках это ломается.
- **Чтение выделения**: `Ctrl+C` и сравнение буфера с тем, что там лежало.
  Не изменился — выделения нет, работаем по буферу (ровно как оранжевые
  действия на телефоне).
- **Этап 2 (по желанию)**: UI Automation через JNA — `TextPattern` отдаёт весь
  текст поля и позицию каретки без всяких `Ctrl+C`. Тогда появляется полный
  паритет с телефоном: правка всего поля без выделения, «текст до курсора» как
  контекст, вставка в середину. Работает в Chrome, Word, Telegram, VS Code;
  в части Electron-приложений — нет, поэтому это надстройка над буферным
  способом, а не замена ему.
- **Горячие клавиши**: JNativeHook (низкоуровневый хук Windows, прав
  администратора не требует).

Клавиши по умолчанию (все меняются в настройках):

| Клавиша | Действие |
|---|---|
| `Ctrl+Alt+Space` | Диктовка: зажал-говоришь-отпустил; короткий тап — переключатель |
| `Ctrl+Alt+C` | Причесать (CLEAN) выделение или буфер |
| `Ctrl+Alt+P` | Меню правки у курсора |
| `Ctrl+Alt+Z` | Отменить последнюю правку |

### 2.5 Ключ Anthropic на компьютере

Тот же ключ, тот же прямой вызов API (прокси на VPS не делаем — договорённость
из README). Хранится в `%APPDATA%\Pravka\settings.json`. Это обычный файл:
если хочется строже — этап 2, шифрование через Windows DPAPI (`CryptProtectData`
по JNA), ключ становится нечитаемым под другой учётной записью Windows.

## 3. Единый словарь: синхронизация через Google-аккаунт

### 3.1 Почему Apps Script, а не Drive API

В Засечке уже работает ровно этот приём: маленькое веб-приложение Apps Script,
привязанное к твоей таблице; секрет — сам URL (`docs/zasechka-sheets.md`).
Никакого OAuth, никаких client secret'ов на двух устройствах, данные лежат в
твоём Google-аккаунте, и их **видно глазами** — таблицу можно открыть и
поправить словарь прямо там, с телефона в браузере.

Полноценный OAuth к Drive API дал бы «настоящий вход через Google-аккаунт», но
потребовал бы регистрации приложения, экрана согласия и хранения refresh-токена
на обоих устройствах. Для одного владельца это плата без выгоды.

### 3.2 Таблица «Правка — общее»

| Лист | Направление | Ключ строки |
|---|---|---|
| `Словарь` | ↔ в обе стороны | `uid` записи |
| `Правила` | ↔ | `uid` |
| `Промпты` | ↔ | имя режима (`CLEAN`, `BUSINESS`, …) |
| `Расшифровки` | ↑ только вверх | `device:id` |
| `Статистика` | ↑ только вверх | `дата:device` |

### 3.3 Протокол — один POST на синхронизацию

```
POST https://script.google.com/macros/s/…/exec
{
  "device": "pixel" | "workstation",
  "since": 1756000000000,        // updatedAt последней успешной синхронизации
  "push": { "dict": [...], "rules": [...], "prompts": [...],
            "transcripts": [...], "stats": [...] }
}
→
{ "serverTime": 1756086400000,
  "pull": { "dict": [...], "rules": [...], "prompts": [...] } }
```

- **Слияние — по записи, по времени правки** (`updatedAt`, кто позже — тот
  прав). Для этого в `DictEntry` и `Rule` добавляются три поля: `uid`
  (генерируется один раз при создании), `updatedAt`, `deleted`. Старые записи
  без `uid` получают его при первой загрузке — формат обратно совместим.
- **Удаление — «надгробием»**, а не пропажей строки: `deleted=true` едет как
  обычная правка, иначе удалённое слово воскресало бы с другого устройства при
  каждом синке. Надгробия старше 90 дней подчищаются.
- **Счётчик срабатываний** складывается: устройство шлёт прирост с прошлого
  синка, таблица прибавляет. Так «сколько раз слово реально спасало» считается
  по обоим устройствам сразу.
- **Расшифровки и статистика** только дописываются (upsert по ключу), поэтому
  конфликтов там нет по определению. Текст расшифровок по умолчанию **не**
  уезжает — только метрики; тумблер «слать текст» есть, но выключен.

### 3.4 Когда синхронизируемся

- при старте приложения (и телефона, и компьютера);
- дальше раз в 12 часов;
- через 30 секунд после ручной правки словаря (чтобы новое слово доехало до
  второго устройства сразу, а не завтра);
- кнопкой «Синхронизировать» в настройках.

Синхронизация — фоновая и не мешающая: не дошло — записи остаются помеченными
неотправленными, следующий заход дошлёт. Ровно как в Засечке.

## 4. Порядок работ

| Этап | Что делается | Результат |
|---|---|---|
| **1** | `scripts/whisper` — сервер, автозапуск, инструкция | Часовая встреча разбирается минуты вместо 10–15; и это уже полезно само по себе |
| **2** | Модуль `:core`, телефон переезжает на него без изменения поведения | Общая логика; APK собирается CI как раньше |
| **3** | Модуль `:desktop`: запись, Whisper, словарь, вставка в поле, горячая клавиша, трей | Диктовка на воркстанции работает |
| **4** | Правка через Claude: CLEAN, меню, стриминг в плашку, отмена | Полный паритет по функциям |
| **5** | Окно вкладок: Словарь, Промпты, Обучение, Расшифровки, Статистика | Словарь правится с клавиатуры |
| **6** | Синхронизация: Apps Script + `SyncStore` в `:core`, на обоих устройствах | Один словарь на телефоне и компьютере |
| **7** (по желанию) | UI Automation, DPAPI, доступ телефона к воркстанционному Whisper по локальной сети | Паритет по мелочам и large-v3 на телефоне дома |
